# Работа нескольких агентов

## Роли

| Роль        | Кто                   | Отвечает                                                                     |
| ----------- | --------------------- | ---------------------------------------------------------------------------- |
| владелец    | человек               | цели, имена, утверждение спек, приёмка                                       |
| ведущий     | основной агент сессии | план, контракты, нарезка, ревью результатов, интеграция, общение с человеком |
| исполнитель | субагент              | одна часть с чётким входом и критерием готовности                            |

## Когда делегировать

Делегируй, только если части **независимы** и каждая заметная (≥ 30 минут работы): два модуля, набор блоков
по готовому `defineBlock`, тесты к готовому сервису, исследование аналогов. Не делегируй: проектирование, изменение
контракта или схемы, задачи на 5 минут, правки одного файла несколькими агентами.

Порядок для фичи на несколько слоёв: ведущий фиксирует **контракт** (`packages/contracts`) и схему БД → параллельно
сервер и клиент → ведущий интегрирует и прогоняет e2e.

## Поручение исполнителю

Исполнитель не видит разговора — поручение самодостаточно:

```
Задача: <что сделать, 1–3 предложения>
Контекст: карточка docs/tasks/<…>.md, спека docs/specs/<…>.md §N
Скиллы: <module, lesson-blocks, testing> — открой и следуй
Вход (зафиксировано, не менять): контракт packages/contracts/src/<m>.ts, таблицы <…>
Можно менять: <пути>
Нельзя: ядро, контракт, миграции, чужие модули; коммитить
Готово, когда: pnpm check зелёный, тесты <…>, e2e <…>
Отчёт: перечень изменений (файл — что — зачем), что не проверено, вопросы
```

Исполнитель работает в отдельном worktree (`isolation: worktree`), если правит код параллельно с другими.

## Приёмка результата

Ведущий **не верит отчёту на слово**: читает diff, запускает `pnpm check` и тесты, проходит `review-checklist`.
Конфликтующие результаты интегрирует сам. Отчёт исполнителя не пересылается человеку целиком — только суть.

## Передача контекста между сессиями

Сессия заканчивается, а задача — нет: запиши `docs/tasks/<задача>/notes/handoff.md` (перезаписывается):

```markdown
# Передача: <дата>

## Где остановились    пункт плана, что сделано в этой сессии

## Состояние кода      ветка, unstaged/staged, что не закоммичено, что падает

## Следующий шаг       конкретное действие и команда

## Решения сессии      что решил человек (с датой) — перенести в task.md/decisions.md

## Открытые вопросы

## Не забыть           ловушки, найденные по ходу
```

Новая сессия начинает с: `AGENTS.md` → `task.md` → `plan.md` → `handoff.md`.

## Журнал

`plan.md` задачи — ход работ: пункт, статус, дата, ссылка на карточку. Решения человека из чата — в `task.md`
(раздел «Решения», с датой), выбор с последствиями — `D-NNN`.

## Остановись и спроси, если

- части оказались зависимыми (исполнители правят одно и то же);
- исполнитель вернул вопрос, решать который должен человек.
