# Отладка

Цель — найти **причину**, а не заглушить симптом. Исправление бага — изменение продукта (`change-workflow`; для
очевидной однострочной ошибки — с согласия человека без полной карточки, но с тестом).

## Шаги

1. **Воспроизвести.** Роль, школа, данные, шаги, ожидаемое/фактическое. Локально — сид или фабрика
   (`local-env`, `testing`). Не воспроизводится — собери больше данных, не гадай.
2. **Падающий тест.** Интеграционный (сервер) или e2e (UI), который падает по той же причине.
3. **Сузить слой.**

| Симптом                         | Где смотреть                                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------------- |
| 400                             | вход не прошёл zod: `issues` в ответе; схема контракта vs то, что шлёт клиент                     |
| 403                             | `can()` процедуры и роль; `permissions.ts` модуля                                                 |
| 404 на существующей записи      | политика (`policies.ts`) или запись другой школы (RLS) — так и задумано?                          |
| пустой список, хотя данные есть | `ctx.db` vs глобальный клиент; `app.school_id` не тот; фильтр политики; RLS                       |
| 500                             | лог по `requestId` (заголовок ответа `x-request-id`), стек; `fail.*` vs необработанное исключение |
| UI не обновился после действия  | `invalidateQueries` после мутации, ключ запроса                                                   |
| реакция «потом» не случилась    | событие: задача подписчика `<модуль>.on.<событие>` поставлена (транзакция не откатилась)? в pg-boss — `failed`? `pnpm jobs:list`, `pnpm jobs:run`                |
| старые уроки ломаются           | миграция таблицы типа блока не заполнила `published`-строки; `copy` типа при публикации           |
| ученик видит старый контент     | урок не переопубликован (`has_unpublished_changes`), кэш опубликованного урока                    |
| разное поведение у школ         | настройки школы, фича-флаги                                                                       |
| только в проде                  | конфиг env, версии миграций, размер данных (план запроса — `performance`)                         |
4. **Причина.** Сформулируй одной фразой: «X, потому что Y (`путь:строка`)». Проверь гипотезу тестом/логом.
5. **Исправить** минимально и в правильном слое (правило в сервисе, а не скрытие в UI). Проверь, нет ли той же
   ошибки в соседнем коде (`grep`) — сообщи, но не чини попутно без согласия.
6. **Проверить.** Тест зелёный, `pnpm check` зелёный, ручная проверка сценария.

## Инструменты

- Логи: `pnpm dev` пишет pino-pretty; фильтр `| grep <requestId>`.
- Окружение: `pnpm env:check` — версии, сервисы, миграции, демо-данные (скилл `local-env`).
- БД: `pnpm db:studio`; SQL под ролью приложения (с RLS) — `docker compose -f docker/compose.yml --env-file .env exec -T postgres psql -U app_user -d dinastia`, внутри
  `select set_config('app.school_id', '<id школы>', false);` — иначе политика скроет все строки школы.
- **Плавающий тест**: `pnpm test:repeat -n 10` (тесты api) или `pnpm test:repeat -n 5 -- <команда>` — например
  `-- pnpm check` (под нагрузкой turbo) или `-- pnpm exec playwright test <спека>`. Лог каждого упавшего прогона
  (и артефакты Playwright) — в `test-results/flaky/<время>/`, в конце — какие тесты падали и сколько раз. Без лога
  причину не установить: не «лечи» ретраями (скилл `testing`). Частые причины в Dinastia: таймаут под нагрузкой
  `pnpm check`, ожидание по времени вместо события, DDL в тесте (deadlock с каскадом школ), общие лимиты better-auth
  при одинаковых адресах клиентов в тестах.
- Задачи: `pnpm jobs:list`, `pnpm jobs:run <name> …`.
- Клиент: React Query Devtools (в dev), вкладка Network (`x-request-id`).

## Остановись и спроси, если

- причина в ядре (`#/kernel`, `packages/ui`) — запрос к ядру или разрешение;
- баг затронул данные (неверные баллы, прогресс) — исправление данных только с решением человека;
- признаки утечки между школами или ответов ученикам — сразу сообщи человеку, это инцидент.
