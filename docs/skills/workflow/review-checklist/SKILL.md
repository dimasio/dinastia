# Ревью

Ревью делает агент (самопроверка перед «готово» — обязательна) или человек. Встроенная команда `/code-review`
ищет баги; этот чек-лист — **правила Dinastia**, применяй вместе.

## Порядок

1. Контекст: карточка изменения/задача — что должно было измениться.
2. `git diff` (или перечень изменений из карточки) — по слоям: миграции → контракт → сервер → клиент → тесты → docs.
3. `pnpm check` и e2e изменения — запусти, не верь на слово.
4. Чек-лист ниже.
5. Замечания.

## Чек-лист

**Данные и тенант**
- [ ] новые таблицы школы — `tenantTable`, связи — `tenantRef` (D-038); нет `school_id` руками; нет глобального клиента БД
- [ ] индексы с `school_id` первым под новые фильтры/сортировки и FK
- [ ] миграция сгенерирована, не правит старые; удаление/переименование — expand/contract и согласовано
- [ ] только реляционная структура: нет `jsonb` кроме `richText()`/`opaqueJson()`, нет массивов-связей и EAV (D-032)

**Права и безопасность** (подробно — `security-baseline`)
- [ ] у каждой процедуры `school` есть `can()`; политики «только свои» применены в `list` и `get`
- [ ] ответ `learn.*` не содержит черновых (`draft`) блоков, правильных ответов, чужих данных
- [ ] вход валидируется zod-схемой контракта; нет `z.any()`/`unknown` без причины
- [ ] файлы private по умолчанию; URL — signed; нет HTML из пользовательских данных (`dangerouslySetInnerHTML`)

**Логика**
- [ ] логика в `service.ts`, handler — одна строка
- [ ] переходы статусов — через одну функцию с таблицей переходов
- [ ] гонки: лимиты и счётчики под блокировкой или атомарно
- [ ] события эмитятся после изменений; подписчики и задачи идемпотентны
- [ ] ошибки — `fail.*` с кодом, код есть в `errors.json`
- [ ] время — `ctx.now()`

**Контракт**
- [ ] не ломает клиентов, или это явно согласовано в карточке

**UI**
- [ ] данные через `orpc` + Query; фильтры в search-параметрах
- [ ] состояния: загрузка, ошибка, пусто, нет прав
- [ ] 360px, клавиатура, `aria-label` у иконок, токены вместо цветов
- [ ] строки через i18n, термины по `docs/specs/glossary.md` (скилл `ux-writing`)

**Тесты**
- [ ] интеграционный тест сервиса, матрица прав, изоляция; e2e основного пути
- [ ] существующие тесты не ослаблены

**Документация**
- [ ] `domain.md`, продуктовый скилл, release notes обновлены (для изменений поведения)
- [ ] решения с выбором — `D-NNN`
- [ ] изменился способ работы — скилл платформы поправлен

## Формат замечаний

```
[блокер] apps/api/src/modules/assessments/quiz.service.ts:88 — попытка стартует без проверки лимита attempts
         при параллельных запросах (нет for update). Предложение: …
[важно]  … 
[мелочь] …
```

Блокер — нарушение безопасности, тенантности, потеря данных, сломанный контракт, падающие тесты. Итог —
«можно мержить / после блокеров / нужна переработка».

## Остановись и спроси, если

- изменение не соответствует утверждённой целевой спеке — сообщи, не «чини» молча;
- ревью требует запуска того, что трогает внешние сервисы.
