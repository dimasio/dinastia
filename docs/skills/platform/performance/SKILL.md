# Производительность

> Статус: сверено с кодом в 5.2 (бюджет веба, индексы внешних ключей, проверка N+1).

## Бюджеты

| Что                             | Бюджет                           |
| ------------------------------- | -------------------------------- |
| процедура API (p95)             | ≤ 200 мс чтение, ≤ 500 мс запись |
| ответ списка                    | ≤ 100 записей, ≤ 200 КБ          |
| начальный JS (общий вход)       | ≤ 200 КБ gzip — `pnpm bundle:budget`, CI (5.2: 186 КБ) |
| ленивый чанк                    | ≤ 200 КБ gzip (редактор rich text — 141 КБ) |
| плеер урока на мобиле (LCP, 4G) | ≤ 2,5 с                          |
| фоновая задача                  | ≤ `timeout`, батчи ≤ 500 записей |

Расчётный масштаб школы для проверок: 50 тыс. учеников, 200 курсов, 5 тыс. уроков, 2 млн записей `lesson_progress`.
Сида большой школы пока нет (цель — нагрузочная проверка на стенде, 5.3); демо-данные — `pnpm db:seed`, `pnpm db:seed:trud`.

## БД

- Каждому фильтру/сортировке списка — индекс `(school_id, …)`; проверяй `EXPLAIN (ANALYZE, BUFFERS)` на сиде
  `large` (`EXPLAIN ANALYZE` в psql под `app_user` с `set_config('app.school_id', …)` — команда в скилле `debugging`): нет `Seq Scan` по большим таблицам.
- Только нужные колонки (`select({ … })`), особенно мимо тяжёлых колонок (`richText` в списках не нужен; блоки урока в списке уроков не грузятся).
- **Индекс под каждым внешним ключом** — `index().on(t.schoolId, t.<ключ>)` рядом с `tenantRef`; проверяет
  `kernel/db/fk-index.test.ts` (иначе удаление урока или участника перебирает дочерние таблицы целиком).
- N+1 — запрещён (скилл `data-access`). Проверка — счётчик запросов `src/test/queries.ts` (`countQueries`): список из 2 и из 6 строк
  делает одинаковое число запросов (`src/n-plus-one.test.ts`: ученики курса, аналитика, кабинет ученика, мои курсы, курсы школы).
  Оглавления нескольких курсов — `publishedOutlines` одним заходом; ссылки на файлы списка — `signFileKey` по ключу из того же
  запроса (`ctx.files.signedUrl` — запрос на файл, только для одиночного).
- `count(*)` по большим выборкам — в списке (`listQuery`/`toPage`); оценка вместо точного числа — когда измерим, что нужна.
- Аналитика — агрегатные запросы по индексам (4.6); таблица-сводка с пересчётом задачей — когда измерим, что запросы не
  укладываются в бюджет (изменение модели — с человеком).
- Пересчёт прогресса — инкрементальный по событию, не «пересчитать всех».

## Клиент

- Маршруты — code splitting автоматически (TanStack Router `autoCodeSplitting`), но **`beforeLoad` и `validateSearch` остаются в
  начальной загрузке**: в них — строки и простые функции (`resourceSearch`, `#/app/search.ts`), не ресурсы, формы и схемы zod
  (`requirePerm('courses.read')`, а не `requirePerm(coursesResource.perms.read)` — иначе ресурс и zod уходят в общий вход).
- Пакеты рабочей области — `"sideEffects": false` (у `ui` — кроме CSS): иначе сборщик не отбрасывает неиспользуемые экспорты
  (`@dinastia/ui/resource` тянул таблицы и формы в каждую страницу — 291 → 186 КБ, 5.2).
- Редакторы блоков, Tiptap, графики, PDF-просмотр — `lazy()`; viewer'ы блоков в плеере — тоже lazy по типу.
- Списки > 100 строк в DOM — постранично (ресурс — 20 по умолчанию); виртуализация — когда понадобится.
- Query: `staleTime` 30 с для справочных данных, prefetch следующего урока в плеере.
- Картинки — варианты из `files` (`card`, `thumb`), `loading="lazy"`, размеры заданы (нет CLS).
- Не тянуть библиотеку ради одной функции (скилл `dependencies`); размер — `pnpm bundle:budget` (CI падает при превышении).

## Кэш

Кэш на сервере — только когда измерено, что нужен; ключ всегда включает `schoolId`; инвалидация — по событиям.
До R3 (Redis) — in-memory LRU в процессе для неизменяемых данных (опубликованный урок по `published_at`).

## Как оптимизировать

1. Измерь (лог длительности процедуры, `EXPLAIN`, профайлер React, отчёт бандла) — без измерения не оптимизируй.
2. Найди узкое место, исправь одно, измерь снова.
3. Зафиксируй тестом/бюджетом (CI проверяет размер бандла).

## Остановись и спроси, если

- оптимизация требует денормализации или новой таблицы-сводки (изменение модели);
- нужен внешний кэш/поиск (Redis, Elasticsearch/OpenSearch, Meilisearch).
