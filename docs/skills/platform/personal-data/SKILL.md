# Персональные данные (152-ФЗ)

Юридические формулировки (политика, согласие, поручение) даёт человек/юрист; скилл — как это отражается в коде.

## Роли

- **Школа** — оператор ПДн своих учеников и сотрудников; Dinastia обрабатывает их **по поручению** школы
  (условия — в оферте).
- **Dinastia** — оператор ПДн владельцев школ (регистрация, биллинг).

## Что считается ПДн у нас

Имя, email, телефон, аватар, IP и user-agent, ответы и файлы учеников, переписка, оценки, сертификаты, история
входов. Свои поля учеников (R3) — по умолчанию ПДн.

## Правила

1. **Хранение в РФ**: БД, файлы, бэкапы, логи, ошибки — только в РФ (D-016). Внешний сервис с ПДн — только
   российский или с согласия человека (скилл `integrations`).
2. **Минимизация**: новое поле о человеке — только если нужно для сценария; согласовать с человеком.
3. **Пометка** в схеме: колонки ПДн — `pii()` обёртка (`email: pii(text('email'))`), это используется для
   маскирования, экспорта и удаления (`check:registries` требует решения «pii / не pii» для колонок с подозрительными
   именами `email|phone|name|address|birth`).
4. **Логи**: pino-редактор маскирует поля `pii` и известные ключи (`email`, `phone`, `password`, `token`);
   не логировать тела запросов целиком.
5. **Согласия**: при регистрации школы — оферта и политика Dinastia; при регистрации ученика — согласие на
   обработку ПДн школой (текст и ссылки — настройки школы `schools.legal`); факт согласия — `consents`
   (кто, что, версия текста, когда, IP).
6. **Доступ сотрудников**: экспорт ПДн — отдельное право (`learning.export`), действие пишется в журнал (`audit`).
7. **Права субъекта**:
   - экспорт «мои данные» — задача собирает JSON/ZIP по ученику в школе (скилл `documents`);
   - удаление ученика из школы — **обезличивание**: имя → «Удалённый ученик», email/телефон — null, файлы удаляются,
     оценки и агрегаты сохраняются для статистики школы; `users` удаляется, если нет других членств.
8. **Удаление школы**: через 30 дней после запроса задача удаляет все данные школы и файлы в S3; бэкапы — по сроку
   хранения бэкапов.
9. **Тестовые данные**: в сидах и тестах — только вымышленные данные; дампы прод-БД локально — запрещены.

## При новом поле/интеграции

- [ ] нужно ли поле; согласовано
- [ ] `pii()`; маскирование в логах
- [ ] участвует в экспорте и обезличивании (функции `exportMemberData`, `anonymizeMember` модуля)
- [ ] видно только нужным ролям
- [ ] передаётся третьим лицам? (почта, видео) — отражено в политике

## Остановись и спроси, если

- нужны особые категории (здоровье, биометрия), паспортные данные, данные детей до 14 лет;
- данные уходят за пределы РФ;
- нужно хранить ПДн дольше срока или после удаления.
