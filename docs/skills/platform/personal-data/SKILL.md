# Персональные данные (152-ФЗ)

Юридические формулировки (политика, согласие, поручение) даёт человек/юрист; скилл — как это отражается в коде.

## Роли

- **Школа** — оператор ПДн своих учеников и сотрудников; Dinastia обрабатывает их **по поручению** школы
  (условия — в оферте).
- **Dinastia** — оператор ПДн владельцев школ (регистрация, биллинг).

## Что считается ПДн у нас

Имя, email, телефон, аватар, IP и user-agent, ответы и файлы учеников, переписка, оценки, сертификаты, история
входов. Свои поля учеников (R3) — по умолчанию ПДн.

## Правила

1. **Хранение в РФ**: БД, файлы, бэкапы, логи, ошибки — только в РФ (D-016). Внешний сервис с ПДн — только
   российский или с согласия человека (скилл `integrations`).
2. **Минимизация**: новое поле о человеке — только если нужно для сценария; согласовать с человеком.
3. **Пометка** в схеме: колонки ПДн — `pii()` из `@dinastia/db` (`email: pii(text('email').notNull())`; пометка
   в config колонки, читает `isPii(column)`). Помечены `users.name/email/image`, `sessions.ip_address/user_agent`,
   `consents.ip`, `invitations.email`, `files.name`, `audit_log.ip`. Пометка нужна для маскирования, экспорта и
   удаления. `check:registries` требует решения «pii / не pii» для колонок с подозрительными именами
   `email|phone|name|address|birth`: `pii()` или запись в `NOT_PII` (`apps/api/src/kernel/registry-check.ts`) с
   причиной — например, `schools.name` (название организации).
4. **Логи**: pino маскирует ключи `SECRET_KEYS` (`kernel/log.ts`: `email`, `phone`, `name`, `password`, `token`,
   `ip`…) на глубине до 2. Ключ каждой `pii()`-колонки обязан быть в этом списке — тест `kernel/pii.test.ts` падает
   на новой колонке с немаскируемым ключом. Не логировать тела запросов и строки таблиц целиком; в журнал действий
   (`ctx.audit`) — тоже без ПДн.
5. **Согласия** (5.5): при регистрации школы — оферта и политика Dinastia (`/legal/offer`, `/legal/privacy`, версии —
   `kernel/legal.ts`, тексты — `apps/web/src/features/legal/texts/`); при присоединении ученика и принятии приглашения
   сотрудника — согласие на обработку ПДн школой: вход процедуры `consent: true`, флажок `PdConsent`, запись
   `recordPdConsent` (`modules/schools/legal.ts`: `pd_processing`, версия шаблона/своей политики + время реквизитов, IP, без
   дублей на ту же версию). Реквизиты — настройки `schools_settings` (оператор, почта для запросов, своя политика), публично —
   `schools.legal`.
6. **Доступ сотрудников**: выгрузка и удаление данных ученика — `schools.pd.manage` (owner, admin), каждое действие — в журнал
   (`learning.student.data-exported`, `learning.student.anonymized`, без ПДн).
7. **Права субъекта** — реестр «данных человека»: модуль объявляет `personalData: definePersonalData({ export, anonymize,
   tables })` (`kernel/personal-data/define.ts`), ядро собирает части всех модулей:
   - выгрузка — `personalDataEntries` → zip-выгрузка `learning.member-data` (`data.json` + файлы; скилл `documents`); ученик —
     свои, администратор — любого ученика;
   - удаление ученика — **обезличивание** `anonymizeMember`: части модулей (тексты → `DELETED_TEXT`/`deletedDoc()`, файлы —
     `ctx.files.remove`, оценки и агрегаты остаются), затем ядро: выгрузки и файлы участника, аватар, согласия этой школы,
     `audit_forget_ip` (функция БД — журнал иначе неизменяем), участник → пользователь-заглушка «Удалённый ученик»
     (`members.status = deleted`, `users.deleted_at`); пользователь без других членств удаляется. Сертификаты аннулируются.
8. **Удаление школы** (`kernel/school-deletion`): школа закрыта сразу, 30 дней на отмену владельцем, затем задача удаляет файлы
   S3 по префиксу, строки (каскад от `schools`) и пользователей без других школ, кроме владельца; бэкапы — по сроку хранения
   бэкапов.
9. **Тестовые данные**: в сидах и тестах — только вымышленные данные; дампы прод-БД локально — запрещены.

## При новом поле/интеграции

- [ ] нужно ли поле; согласовано
- [ ] `pii()`; ключ — в `SECRET_KEYS` (тест `kernel/pii.test.ts`)
- [ ] участвует в выгрузке и обезличивании: часть `definePersonalData` модуля, таблица — в её `tables` (тест-страж
  `learning/personal-data.test.ts`)
- [ ] видно только нужным ролям
- [ ] передаётся третьим лицам? (почта, видео) — отражено в политике

## Остановись и спроси, если

- нужны особые категории (здоровье, биометрия), паспортные данные, данные детей до 14 лет;
- данные уходят за пределы РФ;
- нужно хранить ПДн дольше срока или после удаления.
