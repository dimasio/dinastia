# Проектирование экрана

Сначала утверждённый вайрфрейм — потом код (`web-screens`, `admin-resource`, `ui-kit`). Мелкие правки
существующего экрана — без вайрфрейма.

## 1. Задача экрана

Одним предложением: **кто** (роль), **что делает** (главное действие), **как часто**. Пример: «Куратор каждый день
разбирает новые ДЗ своих групп: открыть, прочитать, ответить, принять/вернуть — за минуту на работу».

## 2. Шаблон

| Шаблон | Когда | Пример | Реализация |
|---|---|---|---|
| **Список** | много однотипных записей, фильтры | курсы, ученики, банк вопросов | `ResourcePage` |
| **Карточка** | одна сущность, разные аспекты | курс (контент, ученики, потоки, настройки) | лэйаут маршрута + `Tabs`, `PageHeader` с действиями |
| **Конструктор** | сборка из частей | урок: палитра блоков · холст · свойства блока | три панели, на мобиле — холст + `Sheet` |
| **Плеер** | последовательное прохождение | урок ученика: оглавление · контент · «Далее» | оглавление в `Sheet` на мобиле |
| **Очередь** | разбор входящих по одному | проверка ДЗ: список · просмотр · ответ | master-detail, клавиши «следующий» |
| **Дашборд** | обзор и переходы | главная школы, аналитика курса | карточки-метрики + списки «требует внимания» |
| **Мастер** | длинное создание по шагам | регистрация школы, импорт учеников | `Steps`, сохранение между шагами |
| **Настройки** | группы параметров | настройки школы, курса | экран из реестра `settings` |

Не изобретай новый шаблон без согласования.

## 3. Вайрфрейм

ASCII в карточке изменения/чате — для утверждения:

```
┌ PageHeader: Проверка заданий ──────────── [Фильтр: группа ▾] [статус ▾] ┐
├──────────────────────┬──────────────────────────────────────────────────┤
│ ● Иванова А. · Урок 3│ Урок 3 «Цвет» · Поток «Осень» · сдано 2 ч назад │
│   2 ч · 1 файл       │ ─────────────────────────────────────────────── │
│ ○ Петров Б. · Урок 2 │ <ответ ученика: текст, файлы>                   │
│   вчера              │ ─────────────────────────────────────────────── │
│ …                    │ переписка                                        │
│                      │ [комментарий…                               ]   │
│ [пусто: «Всё        │ [Вернуть на доработку]  [Принять ✓]  (J/K — ↑↓)  │
│  проверено 🎉»]      │                                                  │
└──────────────────────┴──────────────────────────────────────────────────┘
мобильная: список → тап → просмотр на весь экран, кнопки снизу (sticky)
```

## 4. Обязательные решения

| Вопрос | Ответ в описании экрана |
|---|---|
| роли | кто видит экран; какие элементы скрыты для каких ролей |
| состояния | загрузка (скелетоны), пусто (текст + действие), ошибка, нет прав, 1000+ записей |
| главное действие | одно основное (`Button` primary), остальные — secondary/в меню |
| опасные действия | подтверждение `AlertDialog` с последствиями; необратимое — ввод названия |
| сохранение | явная кнопка или автосохранение (конструкторы — авто, формы — явно) |
| навигация | откуда приходят, куда уходят, что в URL (фильтры, вкладка, выбранная запись) |
| мобильная | что сворачивается, что уходит в `Sheet`, sticky-действия |
| тексты | заголовки, кнопки, пустые состояния — по `ux-writing` |
| e2e | ключевые `data-testid` |

## 5. Утверждение

Покажи человеку: задача экрана, шаблон, вайрфрейм (десктоп + мобильный), таблица п. 4. Жди «ок» или правок.
После — реализация по `web-screens`/`admin-resource`.

## Остановись и спроси, если

- экран не укладывается ни в один шаблон;
- требуется визуальный дизайн (иллюстрации, маркетинговые страницы) — попроси референсы;
- экран для роли, которой нет в `domain.md`.
