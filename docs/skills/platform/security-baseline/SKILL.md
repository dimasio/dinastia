# Безопасность: базовые правила

Глубокий аудит — `/security-review` (Claude Code) + чек-лист `review-checklist`. Этот скилл — правила, которые
соблюдаются в каждом изменении.

## Угрозы

| Угроза | Пример | Защита |
|---|---|---|
| чужая школа | школа A читает учеников B | RLS (`tenantTable`), `ctx.db`, тест изоляции на каждую таблицу |
| IDOR внутри школы | ученик меняет `submissionId` и видит чужое задание | политики «только своё» в `get`/`list`/мутациях, `notFound` |
| ученик против теста | достаёт правильные ответы, продлевает таймер, обходит лимит попыток | `toPublic`, серверный таймер и лимиты под блокировкой (D-020) |
| захват аккаунта | перебор паролей, перехват magic link | rate limit, одноразовые ссылки с коротким сроком, уведомление о входе |
| XSS | скрипт в тексте урока или комментарии | JSON rich text, без `innerHTML`, CSP |
| вредоносный файл | `.html`/`.svg` со скриптом в вложении ДЗ | белый список MIME, `Content-Disposition: attachment` для private, отдельный домен файлов |
| SSRF | embed/вебхук на `http://169.254.169.254` | белый список доменов embed, запросы наружу только через `@/kernel/http` с блоком приватных сетей |
| утечка ПДн | email учеников в логах, экспорт без прав | `personal-data`, редактирование логов, права на экспорт |

## Правила

1. **Вход** — только через zod-схему контракта; строки с `max`, массивы с `max`, числа с границами. Никаких
   `z.any()` на входе.
2. **Доступ** — `can()` на каждой процедуре + политика записи; проверка на сервере, UI только прячет.
3. **HTML** — нет `dangerouslySetInnerHTML` с пользовательскими данными (lint). Rich text — скилл `rich-text`.
4. **Встраивания** (блок `embed`, видео по URL) — белый список хостов в ядре (`kernel/embed-allowlist.ts`:
   YouTube, VK Видео, Rutube, Kinescope, Google Forms/Slides, Miro, Figma…), рендер в `iframe sandbox`.
5. **Файлы** — `defineFilePurpose` с MIME и размером; private по умолчанию; проверка MIME по содержимому на
   `complete`; отдача private — signed URL с `attachment`, домен файлов отдельный от домена приложения.
6. **Исходящие запросы** — только `ctx.http` ядра (таймаут, запрет приватных IP, логирование без секретов).
7. **Секреты** — только env через `kernel/config`; не в коде, не в логах, не в ошибках, не на клиенте.
8. **Rate limit** (ядро, `rateLimit(key, limit)` middleware): вход, magic link, регистрация школы, приглашения,
   старт попытки теста, загрузка файлов, экспорт.
9. **Сессии** — cookie `HttpOnly`, `Secure`, `SameSite=Lax`; CSRF-защита better-auth; смена пароля/блокировка
   участника отзывает сессии.
10. **Журнал действий** — значимые действия сотрудников (смена роли, оценка/принятие задания, удаление, экспорт,
    настройки, публикация) пишутся `ctx.audit('<action>', { entity, id, diff? })`; журнал не редактируется.
11. **Ошибки** наружу — код и безопасное сообщение; стек — только в лог.
12. **Зависимости** — скилл `dependencies`, `pnpm audit` в CI.

## Инцидент

Подозрение на утечку между школами, ответов ученикам или ПДн — **сразу** остановить работу и сообщить человеку:
что, где, с какого момента, затронутые данные. Не «чинить тихо» и не удалять следы (логи).

## Готово, когда

Изменение проходит пункты выше; для нового входа/файла/внешнего URL есть негативный тест (чужая школа, чужая запись,
недопустимый MIME, запрещённый хост).

## Остановись и спроси, если

- нужно ослабить любое правило (публичная процедура, внешний URL картинки, новый тип файла `html/svg`);
- нужна новая точка входа без аутентификации (вебхук провайдера) — только через `integrations` с подписью.
