# Безопасность: базовые правила

Глубокий аудит — `/security-review` (Claude Code) + чек-лист `review-checklist`. Этот скилл — правила, которые
соблюдаются в каждом изменении.

## Угрозы

| Угроза              | Пример                                                              | Защита                                                                                           |
| ------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| чужая школа         | школа A читает учеников B                                           | RLS (`tenantTable`), `ctx.db`, тест изоляции на каждую таблицу                                   |
| IDOR внутри школы   | ученик меняет `submissionId` и видит чужое задание                  | политики «только своё» в `get`/`list`/мутациях, `notFound`                                       |
| ученик против теста | достаёт правильные ответы, продлевает таймер, обходит лимит попыток | `toPublic`, серверный таймер и лимиты под блокировкой (D-020)                                    |
| захват аккаунта     | перебор паролей, перехват magic link                                | rate limit, одноразовые ссылки с коротким сроком, уведомление о входе                            |
| XSS                 | скрипт в тексте урока или комментарии                               | JSON rich text, без `innerHTML`, CSP                                                             |
| вредоносный файл    | `.html`/`.svg` со скриптом в вложении ДЗ                            | белый список MIME, `Content-Disposition: attachment` для private, отдельный домен файлов         |
| SSRF                | embed/вебхук на `http://169.254.169.254`                            | белый список доменов embed, запросы наружу только через `#/kernel/http` с блоком приватных сетей |
| утечка ПДн          | email учеников в логах, экспорт без прав                            | `personal-data`, редактирование логов, права на экспорт                                          |

## Правила

1. **Вход** — только через zod-схему контракта; строки с `max`, массивы с `max`, числа с границами. Никаких
   `z.any()` на входе.
2. **Доступ** — `can()` на каждой процедуре + политика записи; проверка на сервере, UI только прячет.
3. **HTML** — нет `dangerouslySetInnerHTML` с пользовательскими данными (lint). Rich text — скилл `rich-text`.
4. **Встраивания** (блок `embed`, видео по URL) — белый список: `embedService(url)` / `isAllowedEmbed(url)`, адрес для iframe — `embedSrc(url)`
   из `packages/contracts/src/common/embed.ts` (общий: схема блока проверяет ссылку и на сервере, и в редакторе) — YouTube, Rutube, VK Видео, Kinescope, Vimeo, Яндекс Формы, Google Forms; только
   https, без порта и логина в ссылке; рендер в `iframe sandbox`. Новый сервис — с согласия человека.
5. **Файлы** — `defineFilePurpose` с MIME и размером; private по умолчанию; проверка MIME по содержимому на
   `complete`; отдача private — signed URL с `attachment`, домен файлов отдельный от домена приложения.
6. **Исходящие запросы** — только `ctx.http` ядра (таймаут, запрет приватных сетей с проверкой при соединении и на
   редиректах, логирование без тел; скилл `integrations`).
7. **Секреты** — только env через `kernel/config.ts`; не в коде, не в логах, не в ошибках, не на клиенте.
8. **Rate limit**: вход 5/мин, регистрация 5/мин, magic link 3/мин — better-auth (своя таблица). Процедуры —
   middleware ядра `rateLimit` (`kernel/rate-limit/rate-limit.ts`) после звена, дающего субъекта:
   ```ts
   .use(can('schools.members.manage'))
   .use(rateLimit({ name: 'schools.invite', max: 30, windowSeconds: 3600, by: 'member' })) // 'ip' | 'user' | 'member'
   ```
   Фиксированное окно (≤ суток) в таблице `request_limits`, ключ — имя лимита + sha256 субъекта (IP открытым
   текстом не хранится); попытка считается и при ошибке процедуры; превышение — 429 `RATE_LIMITED` с `retryAfter`
   (секунды). Сейчас: `schools.create` 5/ч на пользователя, `schools.invite` 30/ч и `files.upload` 60/10 мин на
   участника. **Новая процедура** старта попытки теста, экспорта, отправки сообщения, публичной формы — с лимитом
   сразу. Тест — `kernel/rate-limit/rate-limit.test.ts`. Лимит по IP считается
   **по IP клиента**, а IP вычисляет только ядро (`kernel/client-ip.ts`): адрес сокета или `X-Forwarded-For` ровно на
   `TRUST_PROXY_HOPS` доверенных звеньев с конца — левую часть цепочки присылает клиент, ей не верим (D-042).
9. **Сессии** — cookie `HttpOnly`, `Secure`, `SameSite=Lax`, общая для `*.<APP_DOMAIN>`; проверка origin/CSRF
   better-auth включена **явно** (`disableOriginCheck: false` — иначе при `NODE_ENV=test` она молча выключена);
   доверенные origin — корень и поддомены школ, поэтому на поддоменах школ исполняется только наш код: свой
   HTML/JS школ (R5) — только на отдельном домене. Смена пароля/блокировка участника отзывает сессии.
10. **Журнал действий** — значимые действия сотрудников (смена роли, оценка/принятие задания, удаление, экспорт,
    настройки, публикация) пишутся `await ctx.audit('<модуль>.<сущность>.<действие>', { entity, id, diff? })` в той
    же транзакции (откат — записи нет); актор — участник запроса, в задаче — система (null); `diff` — что изменилось,
    без ПДн и секретов (`{ role: { from, to } }`). Таблица `audit_log`: у `app_user` нет UPDATE/DELETE (D-048).
    Пример — `modules/schools/members.service.ts` (смена роли, блокировка), тест — `kernel/audit/audit.test.ts`.
11. **Ошибки** наружу — код и безопасное сообщение; стек — только в лог.
12. **Зависимости** — скилл `dependencies`, `pnpm audit` в CI.

## Инцидент

Подозрение на утечку между школами, ответов ученикам или ПДн — **сразу** остановить работу и сообщить человеку:
что, где, с какого момента, затронутые данные. Не «чинить тихо» и не удалять следы (логи).

## Готово, когда

Изменение проходит пункты выше; для нового входа/файла/внешнего URL есть негативный тест (чужая школа, чужая запись,
недопустимый MIME, запрещённый хост).

## Остановись и спроси, если

- нужно ослабить любое правило (публичная процедура, внешний URL картинки, новый тип файла `html/svg`);
- нужна новая точка входа без аутентификации (вебхук провайдера) — только через `integrations` с подписью.
