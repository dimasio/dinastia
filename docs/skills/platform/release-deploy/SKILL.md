# CI, релизы, деплой

Состав, характеристики серверов, конфигурация окружений и масштабирование — [docs/guide/deployment.md](../../../guide/deployment.md); всё про разворачивание дописывать туда.

> Статус: CI — сверено с кодом в фазе 0 (пункт 0.8); инфраструктура и релизы — фаза 5. Агент **не деплоит в prod**
> и не трогает прод-инфраструктуру без прямой просьбы человека в этой задаче.

## CI (каждый PR и main)

`.github/workflows/ci.yml` — то же окружение, что локально (`docker/compose.yml`, `.env` из `.env.example`):

1. `pnpm install --frozen-lockfile`
2. `pnpm env:up` (Postgres 18, SeaweedFS, Mailpit)
3. `pnpm exec playwright install --with-deps chromium` — до `check`: тесты API печатают PDF (`kernel/documents`, D-059)
4. `pnpm check` (lint, typecheck, unit + интеграционные на `dinastia_test`, страж прав, покрытие RLS, `docs:check`)
5. `pnpm db:reset && pnpm db:seed` — все миграции на чистой БД + демо-данные для e2e
6. `pnpm audit --prod --audit-level high`
7. `pnpm e2e`
8. при падении — артефакты Playwright (trace, скриншоты) и логи compose

Красный CI — не мержить. Флейки — чинить (скилл `testing`). Локально та же последовательность — команды выше по
порядку. Отчёт размера бандла — добавить, когда появятся тяжёлые экраны (фаза 2, скилл `performance`).

## Окружения

| Окружение | Что                                             | Данные                                  |
| --------- | ----------------------------------------------- | --------------------------------------- |
| local     | `pnpm dev` + compose                            | сиды                                    |
| stage     | автодеплой `main`                               | сиды + тестовые школы, без реальных ПДн |
| prod      | деплой по тегу `vX.Y.Z` после проверки на stage | реальные                                |

## Образы и запуск

`api` (HTTP), `worker` (pg-boss: задачи, подписчики, расписания), `web` (статические файлы за CDN/nginx).
Один образ сервера с командой `serve | worker | migrate`. Конфиг — env (скилл `settings`).
В образе воркера — Chromium для PDF (`pnpm exec playwright install --with-deps chromium`, версия — по `playwright-core` из
каталога; D-059); `api` браузер не нужен (PDF печатает только задача).

## Миграции при деплое

1. `migrate` выполняется отдельным шагом **до** выката нового кода.
2. Поэтому каждая миграция совместима с **предыдущей** версией кода (expand/contract, скилл `db-schema`):
   добавили колонку nullable/с default → код начал писать → следующий релиз — `not null` / удаление старого.
3. Долгие миграции данных — фоновой задачей батчами, не в шаге `migrate`.
4. Блокирующие операции на больших таблицах (`CREATE INDEX` без `CONCURRENTLY`, смена типа) — нельзя;
   индекс — `CONCURRENTLY` в отдельной миграции без транзакции.

## Фича-флаги

Незавершённая функция мержится выключенной: флаг школы (`settings`, `edit: []`) или флаг окружения
`FEATURE_<NAME>`. Включение — на stage, затем на пилотных школах, затем всем. Флаг удаляется после включения у всех.

## Релиз

1. На stage прошли демо-сценарии и release notes собраны (`docs/guide/product/release-notes.md`).
2. Тег `vX.Y.Z` (semver: мажор — ломающее для школ/API), changelog из Conventional Commits.
3. Деплой: `migrate` → `worker` → `api` → `web`; smoke-тест (`/health/ready`, вход, открыть урок).
4. Мониторинг 30 минут (`observability`).

## Откат

Код — предыдущий тег (миграции совместимы, поэтому откат кода безопасен). Миграции не откатываются вниз —
исправление новой миграцией. Данные — восстановление из бэкапа только решением человека.

## Бэкапы

Managed PostgreSQL: PITR 7 дней + ежедневные снапшоты 30 дней; Object Storage — версионирование и
lifecycle; ежемесячная проверка восстановления на отдельный кластер.

## Домены

`TRUST_PROXY_HOPS` = число прокси перед API, которые дописывают `X-Forwarded-For` (ingress = 1, CDN + ingress = 2);
неверное значение = либо общий лимит входа на всех, либо подделка IP (D-042, скилл `security-baseline`).

`<slug>.<домен>` — wildcard DNS и wildcard TLS-сертификат; файлы — отдельный домен (`files.<домен>`); свои домены
школ — R5.

## Остановись и спроси, если

- просят деплой в prod, доступ к прод-БД или изменение инфраструктуры;
- миграция несовместима с текущим кодом;
- нужен откат с потерей данных.
