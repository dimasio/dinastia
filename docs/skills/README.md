# Скиллы

Скилл — инструкция агенту на задачу: что это, как устроено, шаги с командами, условие окончания, когда остановиться
и спросить. Формат — Agent Skills: `SKILL.md` с шапкой `name`, `description` и телом на markdown.

## Уровни

| Уровень | О чём | Кто применяет |
|---|---|---|
| `workflow/` | как вести работу: изменения продукта, задачи роадмапа | все |
| `product/` | предметная область: процессы, сущности, правила, где реализовано | разработка продукта |
| `platform/` | как строить на Dinastia: модули, БД, API, экраны, реестры | разработка продукта |
| `core/` | как устроено и меняется ядро | только с разрешения человека или в задачах фаз 0–1 |

Продуктовая задача решается двумя уровнями: `product` говорит **что** и **где**, `platform` — **как**.

## Раскладка и имена

```
skills/<уровень>/<скилл>/SKILL.md
skills/<уровень>/<скилл>/templates/   шаблоны кода
skills/product/<процесс>/<подпроцесс>/SKILL.md
```

- `name` = путь внутри уровня через `-` (`product/lms/courses` → `lms-courses`); имена уникальны во всех уровнях.
- Папки с `_` в начале — не скиллы.

## Статус скилла

Пока ядро не реализовано, скиллы `platform` и `core` описывают **целевой** контракт (`docs/specs/architecture.md`).
В теле таких скиллов первая строка — `> Статус: целевой — сверить с кодом в фазе N`. Задача фазы, реализующая
механизм, **обязана** сверить скилл с кодом (сигнатуры, пути, команды) и убрать пометку. Встретил расхождение скилла
с кодом вне такой задачи — верь коду, сообщи человеку, поправь скилл.

## Как написать скилл

- `description` — что и когда, со словами, по которым узнаётся задача («добавь блок», «экран со списком»), путями и
  командами.
- Тело: как устроено → шаги с командами → готово, когда → «Остановись и спроси, если». До ~250 строк.
- Без особенностей конкретного агента; ссылки на скиллы — по имени, на документы — путём от корня.

## Добавить скилл

1. Папка и `SKILL.md`.
2. Строка в таблице `AGENTS.md`.
3. `pnpm skills:link` (до фазы 0 — `bash tools/skills-link.sh`).
4. `pnpm docs:check`.
