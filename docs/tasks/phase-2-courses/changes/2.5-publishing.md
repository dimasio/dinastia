# 2.5: публикация урока и курса — статусы, проверка готовности блоков

Задача: [phase-2-courses](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап, пункт 2.5: «Публикация урока/курса, статусы, предупреждения при удалении блоков с ответами».

Что сейчас:

- Механизм ядра готов (1.3, D-033): `publishBlocks` копирует черновик урока в `published` с теми же `block_key`
  одной транзакцией (`apps/api/src/kernel/blocks/blocks.ts:177`), `listPublicBlocks` отдаёт опубликованное через
  `toPublic` (`blocks.ts:110`). Из API они не вызываются.
- `lessons.published_at`, `lessons.has_unpublished_changes` есть в схеме (`apps/api/src/modules/courses/schema.ts:58`);
  флаг ставится при каждой правке блоков (`apps/api/src/modules/courses/blocks.service.ts:25`), но никогда не
  снимается — публиковать нечем.
- Статусы курса `draft`/`published`/`archived` есть; из `draft` в `published` перевести нельзя — процедуры нет
  (есть только «В архив», `service.ts:153`). Право `courses.publish` объявлено и ни к чему не привязано
  (`permissions.ts:7`).
- В конструкторах (2.2, 2.3) кнопки «Опубликовать» нет; у урока статус не показан, у курса — только бейдж статуса.
- Правило `domain.md` §3: удалить блок, на который есть ответы, — только с подтверждением. Ответов пока нет: таблиц
  `block_progress`, попыток и сдач ещё нет (фазы 3–4).
- Открытый вопрос из 2.1/2.4: блок с пустыми обязательными полями сохраняется в черновике — что с ним при публикации.

Нужно: преподаватель публикует урок и курс, видит, где есть неопубликованные изменения; незаполненные блоки к ученику
не попадают.

Варианты проверки готовности:

- **(выбран)** замечания объявляет тип блока (`issues` в реестре) — новый тип сам знает, что у него обязательно;
  экран и сервер берут одно и то же;
- строгая схема «для публикации» рядом со схемой черновика — дублирует схему и сложнее для генератора;
- без проверки — ученик увидит пустую рамку видео.

Предупреждение об ответах: в 2.5 — **точка расширения без поведения**. Ответы появятся в фазе 3 (`assessments`) и 4
(`learning`); тогда при публикации урока, из черновика которого удалён блок с ответами, сервер вернёт
`LESSON_REMOVES_ANSWERED_BLOCKS` со списком, а экран — подтверждение (`confirmRemoval: true`). Записываю пунктом в
«Открытые вопросы фазы», чтобы закрыть в фазе 3.

Что не трогаем: правила доступа и завершения (2.6), снятие с публикации, возврат из архива, расписание публикации.
Название урока, порядок и настройки урока не версионируются — меняются у учеников сразу (как сейчас); версионируются
только блоки (D-033).

Риски: публикация урока с сотней блоков — одна транзакция с копированием строк; для MVP приемлемо, бюджет проверю
на демо-уроке (`performance`).

### Вопросы владельцу

1. **Ядро**: добавить в `defineBlock` необязательное `issues(data)` (замечания «не готов к публикации») и проверку
   его строк в `check:registries` — разрешаете эту правку ядра?
2. **Незаполненные блоки**: **блокировать** публикацию урока со списком блоков (рекомендую: ученик не увидит пустую
   рамку, преподаватель сразу видит, что поправить) или **пропускать** их (урок публикуется без них)?
3. **Публикация курса**: уроки публикуются **по одному** в конструкторе урока + в конструкторе курса «Опубликовать
   изменения (N)» сразу для всех; курс публикуется отдельной кнопкой (рекомендую) — или «Опубликовать курс» сразу
   публикует и все уроки?
4. **Снятие с публикации** (курс обратно в черновик, урок скрыть от учеников) — не делаем в 2.5 (у курса есть «В
   архив»), подходит?

Ответы (2026-11-01): рекомендации одобрены — 1) правка ядра `issues` разрешена; 2) незаполненные блоки
**блокируют** публикацию урока; 3) уроки — по одному + «Опубликовать изменения (N)», курс — отдельной кнопкой;
4) снятия с публикации в 2.5 нет.

Утверждено: владелец, 2026-11-01.

| тесты | ядро — замечания и неизменная публикация (`kernel/blocks/blocks.test.ts`); API — `modules/courses/publish.test.ts` (статусы, пустой урок, курс, «все или ни одного», журнал, права, изоляция); unit — `packages/blocks/src/content.test.tsx`; OpenAPI — три пути; e2e `tests/e2e/publishing.spec.ts` со снимками |

Отступления от §2–3 (проще при том же поведении):

- замечания в API списка блоков не добавлены — экран считает их сам той же функцией реестра (`blockDataIssues`),
  сервер проверяет при публикации; поле `status` урока в контракте не добавлено — `lessonStatus()` из полей;
- прибавлено правило «урок без блоков не публикуется» (`LESSON_EMPTY`) — иначе ученик получит пустую страницу;
- на телефоне кнопки не прячутся в «⋯», а переносятся строкой ниже названия (снимки 375px — без наложений).

Проверки: `pnpm check` — ok; e2e — 33/33 (в полном прогоне один раз упал существующий `questions.spec` — песочница
вопросов не открылась за 5 с; повтор зелёный, к 2.5 не относится — записано в «Открытые вопросы фазы»). Миграций нет.
Не проверено: подписчики событий (их пока нет — фаза 4).
