# 2.7: обложка курса, блоки «Картинка» и «Файл», картинки в тексте

Задача: [phase-2-courses](../task.md) · Шаг: 3 — на утверждение

## 1. Запрос

Источник — роадмап, пункт 2.7 «Обложки, загрузка медиа через `files`»; из карточки 2.4 сюда перенесены блоки
`image`, `file` и картинки внутри текста.

Что сейчас:

- Файлы школы готовы (1.7): назначение `defineFilePurpose`, загрузка `createUpload` → PUT в S3 → `complete`
  (`apps/api/src/kernel/storage/files.ts`), чтение — только по подписанной ссылке (`ctx.files.signedUrl`,
  `signFileKey`, час по умолчанию), в вебе — `uploadFile()` (`apps/web/src/app/files.ts`) и `ImageInput`
  (`@dinastia/ui`). Образец — аватар (`modules/schools/files.ts`).
- Картинки в форматированном тексте поддержаны механизмом (1.12): узел `image` с `fileId` в профиле `lesson`,
  `RichTextEditor` с `uploadImage`, `RichTextView` с `resolveFile`, `collectFileIds(doc)`. В продукте не подключены —
  у блока «Текст» кнопки картинки нет.
- `domain.md` §1: у `courses` есть `cover_file_id`; в схеме колонки нет (`modules/courses/schema.ts`).
- **Пробел ядра** (карточка 2.4): `toPublic` — чистая функция, а блоку с файлом нужен адрес файла — подписанная ссылка,
  которую выдаёт только сервер с контекстом школы. Ни конструктору, ни плееру сейчас неоткуда взять ссылку на файл
  блока; хосты блоков (`BlockEditorHost`) не умеют загружать файлы.

Нужно: у курса — обложка; в уроке — картинки (отдельным блоком и внутри текста) и файлы для скачивания.

## 2. Архитектура

| Назначения файлов | `modules/courses/files.ts`: `courses.cover` (обложка), `courses.lesson-image` (картинки урока — блок и текст), `courses.lesson-file` (файлы урока); право — `courses.manage`; лимиты — константы в `packages/contracts/src/courses.ts` (их же проверяет форма) | `files-media` |

| Блоки | `pnpm gen:block image`, `pnpm gen:block file`: редактор — загрузка (`ImageInput` / выбор файла) с прогрессом, просмотр — картинка по ширине / карточка файла с размером и «Скачать»; `issues` — «нет картинки» / «нет файла»; `text` — `files: collectFileIds(body)`, кнопка картинки в редакторе | `lesson-blocks`, `rich-text` |
| Сервис | `blocks.service.ts`: при сохранении блока новые `fileId` — проверка `ready`, назначение `courses.lesson-*`, загрузил этот участник (`FILE_INVALID`); `updateCourse` — `coverFileId` (`courses.cover`), прежняя обложка — `ctx.files.remove`; `Course` в ответе — `coverUrl` | `data-access`, `files-media` |
| Контракт API | **добавление**: `LessonBlock.files`, `CourseUpdate.coverFileId` (`null` — убрать), `Course.coverUrl` | `api-endpoints` |
| UI | конструктор курса — обложка в шапке (`ImageInput`: загрузить, заменить, убрать); конструктор урока — новые блоки в разделе палитры «Медиа», картинки в блоке «Текст» | `web-screens`, `ui-kit` |
| Строки | `blocks:image.*`, `blocks:file.*`, `courses:builder.cover.*` | `i18n` |

Варианты получения ссылок на файлы блока:

- **(выбран)** блок объявляет, на какие файлы ссылается (`files`), ядро подписывает их пачкой и кладёт рядом с
  данными; просмотр берёт адрес по `fileId`. `toPublic` чистая, в БД — только `file_id`;
- асинхронный `toPublic(data, ctx)` — ломает контракт реестра и проверку секретов на `example()`;
- публичные ссылки без подписи — противоречит D-047.

Что не трогаем: превью и нарезку картинок (`file_variants` — позже), загрузку видео (2.4b), обложку в каталоге ученика
(2.6 / фаза 4), квоты школы. Удалённые из урока картинки и файлы в хранилище **остаются** (на них может ссылаться
опубликованная версия) — очистка сирот отдельной задачей позже.

Риски: ссылка живёт ограниченное время — урок, открытый дольше срока, теряет картинки до перезагрузки; предлагаю 6 ч
для медиа урока (вопрос 4). Безопасность: в `mime` назначений нет `text/html`, `image/svg+xml` (исполняемое
браузером); файл урока скачивается с `Content-Disposition: attachment`.
