# 2.3: конструктор урока — блоки из палитры, порядок, автосохранение, предпросмотр

Задача: [phase-2-courses](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап, пункт 2.3. Сейчас: механика блоков — с фазы 1 (`apps/api/src/kernel/blocks/blocks.ts`:
`createBlock`, `updateBlock`, `removeBlock`, `reorderBlocks`, `listBlocks`; хосты `BlockEditorHost`, `BlockViewerHost`,
`BlockPalette` в `@dinastia/blocks/client`; тип блока пока один — «Выноска», остальные — 2.4). Процедур API для
блоков урока и экрана урока нет; в конструкторе курса пункт «Открыть урок» выключен («скоро»).

Нужно: экран урока, где преподаватель собирает урок из блоков: добавить из палитры, править, переставить, удалить,
посмотреть, как увидит ученик. Правки — черновик (D-033); публикация — 2.5.

## 2. Архитектура

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| БД | **ничего** (`lesson_blocks`, таблицы типов — фаза 1; `lessons.has_unpublished_changes` — 2.1) | — |
| Контракт | `courses.blocks.list({ lessonId })` (черновик с полными данными), `create({ lessonId, type, index? })`, `update({ id, data })`, `move({ id, index })`, `remove({ id })`; `courses.lessons.get({ id })` (урок + курс для шапки). Добавление, ничего не ломает | `api-endpoints` |
| Сервис | тонкая обёртка над `kernel/blocks` в модуле courses: урок существует (иначе `LESSON_NOT_FOUND`), любая правка черновика ставит `lessons.has_unpublished_changes = true` (domain.md §3), удаление блока — в журнал | `data-access`, `lesson-blocks` |
| Права | чтение — `courses.read`, правки — `courses.manage` | `permissions` |
| UI | маршрут `/admin/courses/$courseId/lessons/$lessonId`, шаблон «Конструктор»: палитра · холст (широкий экран), холст + «+ Блок» в `Sheet` (телефон); блок на холсте — карточка с редактором типа (`BlockEditorHost`), ручкой и меню «Выше / Ниже / Удалить»; индикатор сохранения; переключатель «Редактор / Как увидит ученик»; в конструкторе курса «Открыть урок» и клик по уроку ведут сюда | `web-screens`, `screen-design`, `lesson-blocks` |
| Строки | `courses:lesson.*` | `i18n` |

Ядро не трогаем. Не делаем: публикацию и статусы (2.5), обязательность блока и настройки урока — режим доступа,
правило завершения (2.6), новые типы блоков (2.4), картинки в тексте (2.7).

## 3. Целевая спецификация

**Задача экрана:** преподаватель наполняет урок содержимым: часто и подолгу, правит маленькими шагами — изменения
не должны теряться, кнопки «Сохранить» нет.

```
┌ ← Основы акварели   Бумага, кисти, краски    ● Сохранено   [Редактор | Как увидит ученик] ┐
├──────────────────────┬────────────────────────────────────────────────────────────────────┤
│ Добавить блок        │ ⠿ Выноска                                                       ⋯ │
│ ТЕКСТ                │   Тип [Внимание ▾]                                                │
│ [! Выноска        ]  │   Текст [B I <> 🔗 …]  Возьмите бумагу плотностью от 200 г/м²     │
│ МЕДИА (2.4)          │                                                                    │
│ …                    │ ⠿ Выноска                                                       ⋯ │
│                      │   …                                                                │
│                      │ пусто: «Урок пустой. Добавьте первый блок из палитры слева.»       │
└──────────────────────┴────────────────────────────────────────────────────────────────────┘
⠿ — ручка; ⋯ — Выше · Ниже · Удалить. Новый блок — в конец урока.
мобильная (375): шапка в две строки, холст в одну колонку, внизу sticky «+ Блок» → палитра в Sheet; без ручек
```

| Вопрос | Решение |
| --- | --- |
| роли | `courses.manage` — правит; `courses.read` (куратор) — видит урок в режиме «Как увидит ученик», без редакторов |
| состояния | загрузка — скелетон; пусто — текст и палитра; ошибка сохранения — индикатор «Не сохранено» + тост, правка остаётся на экране, повтор при следующей правке; урока нет — экран ошибки |
| сохранение | автоматически через 0,5 с после правки блока (проверка схемой типа на клиенте — неверное не отправляется, у блока пишется «Проверьте поля блока»); перестановка, добавление, удаление — сразу; индикатор «Сохраняем… / Сохранено / Не сохранено» |
| предпросмотр | переключатель «Как увидит ученик» — просмотр черновика глазами ученика (через `toPublic` типа, как на сервере); опубликованная версия — 2.5 |
| опасные действия | удалить блок — подтверждение |
| навигация | из конструктора курса (клик по уроку / «Открыть урок»), обратно «← <курс>»; в адресе — id курса и урока |
| мобильная | без ручек, порядок — из меню; палитра — в нижнем `Sheet` по кнопке «+ Блок» |
| e2e | `lesson-editor`, `lesson-block`, `lesson-save-state`, `lesson-preview-toggle`, `block-palette-<type>` |

Правило предметной области (domain.md §3, есть): «Любая правка черновика ставит `has_unpublished_changes = true`».
Новых правил нет.

### Уточнения — ответы владельца (2026-11-01)

1. **Шаблон**: две панели — палитра и холст, редактор блока прямо в карточке на холсте (без отдельной панели
   «свойства»: у блоков мало полей) — подходит?
2. **Автосохранение** через 0,5 с после правки с индикатором «Сохранено», без кнопки «Сохранить» — подходит?
3. **Предпросмотр** — переключатель «Редактор / Как увидит ученик» на том же экране, показывает черновик — подходит?
4. **Отложить** обязательность блока и настройки урока (доступ, завершение) до плеера (2.6) — подходит?

Ответы: все четыре — по рекомендации.

Утверждено: владелец, 2026-11-01.

## 4. Разработка

| Что | Где |
| --- | --- |
| контракт | `packages/contracts/src/courses.ts`: `LessonBlock`, `LessonWithCourse`; `courses.lessons.get`, `courses.blocks.list/create/update/move/remove` |
| сервис | `apps/api/src/modules/courses/blocks.service.ts` — обёртка над `kernel/blocks`: урок существует (`LESSON_NOT_FOUND`), правка → `has_unpublished_changes = true`, удаление блока → журнал `courses.block.removed` |
| процедуры | `apps/api/src/modules/courses/router.ts`: чтение — `courses.read`, правки — `courses.manage` |
| экран | маршрут `apps/web/src/routes/admin/courses/$courseId_.lessons.$lessonId.tsx` (вне вложенности карточки курса), `apps/web/src/features/courses/lesson-editor/lesson-editor.tsx` — палитра (липкая на широком экране, в `Sheet` по «+ Блок» на телефоне), холст с dnd-kit и меню «Выше / Ниже / Удалить», индикатор «Сохраняем… / Сохранено / Не сохранено», предупреждение браузера при уходе во время сохранения, «Как увидит ученик» через `toPublic` |
| конструктор курса | название урока — ссылка в конструктор урока, пункт «Открыть урок» включён |
| строки | `courses:lesson.*`, `builder.openLesson` — без «(скоро)» |
| демо-данные | `pnpm db:seed`: в уроке «Бумага, кисти, краски» — выноска-совет (отдельный шаг, дополняет и ранее засеянную базу) |
| тесты | API `modules/courses/blocks.test.ts` (палитра → данные по умолчанию, позиция, правка по схеме, порядок, удаление в журнал, куратор, изоляция школ), путь OpenAPI в `router.test.ts`; e2e `tests/e2e/lesson-editor.spec.ts` (сборка урока, перетаскивание, перезагрузка, предпросмотр, удаление, «Открыть урок»; телефон; куратор) со снимками |

Найдено по пути и исправлено сразу:

- **Переименование из меню ⋯ в конструкторе курса закрывалось само** под нагрузкой: Radix при закрытии меню
  возвращал фокус на ⋯, поле теряло фокус и сохранялось без правки. Теперь после «Переименовать» фокус остаётся в
  поле (`onCloseAutoFocus`). Ловилось только в полном прогоне e2e.
- **Сценарии куратора искали демо-курс на первой странице списка**, а e2e копят курсы в демо-школе (24 > 20 на
  странице) — помощник `openDemoCourse()` в `tests/e2e/fixtures.ts` открывает его через поиск.
- `courses.spec.ts` — длинный сценарий, в общем прогоне (несколько воркеров) выходил за 30 с: `test.setTimeout(90_000)`,
  как у остальных длинных.

Отступлений от вайрфрейма нет. Проверки: `pnpm check` — ok; e2e — 30/30 (два прогона подряд). Миграций нет.
