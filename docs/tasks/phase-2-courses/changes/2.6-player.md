# 2.6: плеер урока ученика

Задача: [phase-2-courses](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап 2.6 «Плеер урока ученика: навигация по курсу, правила доступа (`open`/`sequential`/`drip`), отметка
просмотра» и демо фазы 2: ученик (зачисленный сидом) проходит уроки последовательно.

Что сейчас:

- Курс, разделы, уроки, опубликованные блоки готовы (2.1–2.7): ученику нужны только опубликованные строки через
  `toPublic` (`listPublicBlocks` в `kernel/blocks`, с подписанными ссылками на файлы), `lessons.published_at`,
  `courses.status`, режимы доступа уроков (`access_mode`, `drip_days`, `drip_date`, `completion_rule`) — всё в схеме.
- Области `learn` в вебе есть (`/learn`, лэйаут `LearnShell`), экран — пустое состояние «нет курсов».
- Нет: зачисления (`enrollments`), прогресса (`lesson_progress`), модуля `learning`, процедур `learn.*`, плеера.
  Полный модуль `learning` (зачисление вручную/по приглашению/ссылке, потоки, кураторы, сроки, дедлайны) — фаза 4.
- Сид демо-курса уроки **не публикует** (открытый вопрос плана).

Нужно: ученик видит свои курсы, открывает курс, проходит уроки с учётом режимов доступа, урок отмечается пройденным.

| Веб | `/learn` — «Мои курсы» (карточки с обложкой и прогрессом); `/learn/courses/$courseId` — оглавление (закрытые уроки видны с причиной); `/learn/courses/$courseId/lessons/$lessonId` — плеер: блоки через `BlockViewerHost`, боковое оглавление (на телефоне — `Sheet`), «Назад / Далее», «Завершить урок» при `manual` | `web-screens`, `ui-kit`, `screen-design` |
| Сид | демо-курс публикуется (уроки и курс), `student1@demo.local` зачисляется внутренней `enrollMember` | `local-env` |
| Строки | `learning:*` (новый namespace), `errors:LESSON_LOCKED`, `ENROLLMENT_NOT_FOUND` | `i18n` |
| Тесты | интеграционные: три режима доступа и истечение, `toPublic` (черновик и секреты не уходят), изоляция школ, права, идемпотентность `complete`, пересчёт прогресса; e2e `tests/e2e/phase-2.spec.ts` — демо фазы (2 раздела, 5 уроков, публикация, ученик проходит последовательно), снимки светлой/тёмной темы и 375px | `testing`, `visual-review` |

Ядро (`kernel/**`, `packages/ui/**`) **не трогаем**: модуль, события и задачи — штатные. Всё, чего не хватит, — запрос
`docs/tasks/requests/…`.

Варианты хранения доступности:

- **(выбран)** вычислять при чтении из зачисления, порядка уроков и `lesson_progress`: нет рассинхронизации, ничего не
  пересчитывается при публикации нового урока;
- хранить `lesson_progress.status` (`locked/available`) по `domain.md` — нужен пересчёт по событиям и задаче drip;
  делаем в фазе 4, когда появятся сроки по потокам и дедлайны (тогда `status` материализуем, не ломая API).

Что не трогаем: зачисление через интерфейс, потоки, кураторов, дедлайны, сертификаты, аналитику (фаза 4); блоки с
ответами (`quiz`, `assignment`) и их влияние на завершение (фаза 3); `all_blocks` пока равен `view` — нет блоков,
требующих выполнения; предпросмотр урока сотрудником уже есть (2.3).

Риски: `sequential` и порядок считаются по «опубликованным» урокам — скрытие/публикация урока меняет доступность
следующих; новый опубликованный урок в курсе зачисленного не снимает `completed` с курса (правило MVP из скилла).

### Вопросы владельцу

1. **Зачисление в 2.6.** Ранее я советовал «плеер только для сотрудников до фазы 4». Это не сходится с демо фазы
   («ученик, зачисленный сидом, проходит уроки»), поэтому рекомендую иначе: **минимальные `enrollments` и
   `lesson_progress`** в новом модуле `learning` (без экранов зачисления), зачисление — сидом и в тестах. Подходит
   ли? Имя модуля `learning` и namespace API `learn` — по `domain.md`/скиллам, подтвердите.
2. **Доступность** считается при чтении (без `locked/available` в БД) — подходит?
3. **Закрытые уроки** видны в оглавлении с причиной (а не скрыты) — подходит?
4. **Завершение:** `view` — при открытии, `manual` — кнопкой, `all_blocks` = `view` до блоков с ответами (фаза 3) —
   подходит?
5. **Сид:** публиковать демо-курс и зачислять `student1@demo.local` — подходит?
6. **Архив и срок:** архивный курс остаётся доступным зачисленным; по `expires_at` — «Доступ закончился» — подходит?

Ответы (2026-11-07): рекомендации одобрены по всем шести вопросам (минимальные `enrollments` и `lesson_progress`, доступность
при чтении, закрытые уроки видны с причиной, правила завершения, сид зачисляет `student1`, архив и срок).

Утверждено: владелец, 2026-11-07.
