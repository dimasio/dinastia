# 2.4b: загрузка видео в Kinescope

Задача: [phase-2-courses](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап 2.4 / решение D-011 (видео через интерфейс провайдера, Kinescope по умолчанию).

Что сейчас:

- Блок `video` (2.4) принимает только **ссылку** (YouTube, Rutube, VK, Kinescope, Vimeo); `toPublic` отдаёт `embedSrc`.
- Ядро готово к провайдерам: `ctx.http` (таймауты, запрет приватных сетей), вебхуки `POST /api/webhooks/<provider>/<schoolId>`
  с подписью, идемпотентностью и задачей `webhooks.process` (`kernel/webhooks`, образец — `fake`), задачи pg-boss.
- Нет: интерфейса `VideoProvider`, `KINESCOPE_*` в `config.ts`, статуса обработки видео, режима «загрузить файл» в блоке.

Нужно: преподаватель загружает видеофайл прямо в блоке, видит статус обработки, ученик смотрит защищённый плеер.

## 2. Архитектура

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| Ядро (**блокер**, нужно разрешение) | `kernel/video/provider.ts` — интерфейс `VideoProvider` (`createUpload`, `getStatus`, `playerSrc`), `kinescope.ts`, `fake.ts`; `config`: `VIDEO_PROVIDER=fake\|kinescope`, `KINESCOPE_TOKEN`, `KINESCOPE_PROJECT_ID`, `KINESCOPE_WEBHOOK_SECRET`; `ctx.video` в контексте; провайдер вебхуков `kinescope` | `core-kernel`, `integrations` |
| БД | **миграция** (только добавление): `video_uploads` (тенантная: `block_id`, `provider`, `video_id`, `status` processing/ready/failed, `error`, `created_by`); `block_video` — `source` (`link`/`upload`), `upload_id` | `db-schema` |
| Загрузка | браузер → наш API `courses.video.createUpload` (право `courses.manage`, лимит) → Kinescope `POST uploader.kinescope.io/v2/init` с токеном платформы → клиент грузит файл **напрямую в Kinescope по tus** (трафик мимо нашего сервера) | `integrations`, `files-media` |
| Статус | вебхук Kinescope `media.update.status` → `webhooks.process` → обработчик модуля `courses` (`done` → ready, `error` → failed), идемпотентно; запасной путь — периодическая задача `courses.video-sync` опрашивает `getStatus` для зависших `processing` | `background-jobs`, `integrations` |
| Блок `video` | режим «Загрузить файл» рядом со ссылкой; статус «Обрабатывается…» / «Готово» / «Ошибка» (опрос карточки, пока `processing`); `issues`: «нет видео» и «видео не обработано» (урок с `processing`/`failed` не публикуется); `toPublic` — `src` плеера, без токена платформы | `lesson-blocks` |
| Контракт API | **добавление**: `courses.video.createUpload`, `courses.video.status`; в данных блока — `source`, `status` | `api-endpoints` |
| Строки / тесты | `blocks:video.upload.*`; unit на фейке (создание, вебхук, повтор, подпись), `tests/e2e/video.spec.ts` на фейк-провайдере | `i18n`, `testing` |

Токен платформы — в env, **не** хранится у школы (D-011); ключ школы — позже, если понадобится.

Что не трогаем: DRM и доменные ограничения плеера, субтитры, квоты школы, удаление видео в Kinescope при удалении блока
(как с файлами 2.7 — очистка отдельной задачей).

Риски и **проверка по документации** (WebSearch, 2026-11-07; `docs.kinescope.com` из песочницы не открылся — детали
сверить в начале разработки):

- загрузка: `POST https://uploader.kinescope.io/v2/init` с `Authorization: Bearer <токен>` и `parent_id` в теле, ответ —
  адрес tus; файл клиент шлёт сам;
- вебхук: событие `media.update.status` (в доках также pre-processing, processing, aborted, done, error, suspended);
- **подпись вебхука в найденных материалах не описана**. По правилам скилла `integrations` без подписи не продолжаем:
  нужно подтвердить механизм (секрет/заголовок) до реализации; запасной вариант — доверять только опросу `getStatus`;
- ПДн: в Kinescope уходит только видео и название (без данных учеников); сервис российский.

### Вопросы владельцу

1. **Ядро**: `VideoProvider`, `ctx.video`, `KINESCOPE_*` в config, провайдер вебхуков `kinescope` — разрешаете правку ядра?
2. **Загрузка**: клиент грузит прямо в Kinescope по tus (рекомендую: файл не идёт через наш сервер) или через нас?
3. **Лимит** размера видео — 2 ГБ на файл (рекомендую; свой у Kinescope тоже есть) — подходит?
4. **Подпись вебхука**: у вас есть аккаунт и доступ к настройкам вебхуков Kinescope? Подтвердить механизм подписи; если
   её нет — только опрос `getStatus` (задержка до минуты) вместо вебхука — подходит?
5. **Ключ школы** (свой аккаунт Kinescope у школы) — не нужен сейчас, откладываем?

Ответы (2026-11-07): рекомендации одобрены — правка ядра разрешена; клиент грузит прямо в провайдера (tus); лимит 2 ГБ;
вебхука нет (подпись не подтверждена) — статус опросом; ключ школы откладываем.

Утверждено: владелец, 2026-11-07.
