# 3.1: банк вопросов курса и теги

Задача: [phase-3-assessments](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап 3.1 «Модуль `assessments`: банк вопросов курса (ресурс), теги».

Что сейчас:

- Ядро вопросов готово (фаза 1): таблицы `questions`/`question_items` (`@dinastia/db`), `kernel/questions` —
  `createQuestion`, `updateQuestion` (правка на месте), `reviseQuestion` (новая ревизия, D-035), `archiveQuestion`,
  `listQuestions` (весь банк курса без фильтров), `publicQuestion` (`toPublic`), `reviewQuestion`, `gradeAnswer`;
  реестр типов `@dinastia/questions` — пока один тип `single_choice`; редактор и просмотр —
  `QuestionEditorHost`/`QuestionViewerHost` (песочница `/dev/questions`). Внешний ключ `questions.course_id → courses`
  уже есть (миграция `0008`).
- Нет: модуля `assessments`, экрана банка, тегов (`question_tags`, `question_tag_links`), API банка, прав.

Нужно: преподаватель ведёт банк вопросов курса — создаёт и правит вопросы, ставит теги, ищет и фильтрует, убирает из банка.
Тест (3.3) будет брать вопросы из этого банка.

| Строки | `assessments:*` (новый namespace), `errors:QUESTION_*`, `TAG_*` | `i18n` |
| Тесты | интеграционные: создание/правка/архив, теги (создание по имени, регистр, лимиты, переименование, удаление), фильтры и поиск, права (куратор — чтение), изоляция школ, `toPublic` без верных ответов в «как увидит ученик»; e2e `tests/e2e/question-bank.spec.ts` со снимками | `testing`, `visual-review` |

Ядро (`kernel/**`, `packages/ui/**`, `packages/questions/src/define.ts`) **не трогаем**. Не хватит — запрос
`docs/tasks/requests/…`.

Варианты:

- Теги: **(выбран)** свободные по имени — быстро для преподавателя; справочник заранее — лишний экран;
- Редактор вопроса: **(выбран)** отдельный экран с явным «Сохранить» — у вопроса есть проверка схемы (варианты, верный
  ответ), автосохранение (как в уроке) сохраняло бы заведомо неполные черновики; всплывающая панель тесна для вариантов.

Что не трогаем: новые типы вопросов (3.2), блок `quiz` и выбор вопросов в него (3.3), импорт/экспорт банка, копирование
банка между курсами, версии вопросов в интерфейсе (ревизии — с попытками, 3.3).

Риски: до 3.3 «ответов нет», поэтому правка всегда на месте; когда появятся попытки — подключается `reviseQuestion` без
изменения API. Уникальность тега без учёта регистра — индекс по `lower(name)` (ручная правка миграции).

### Вопросы владельцу

1. **Теги** — свободные по имени, с переименованием и удалением в диалоге «Теги курса»; до 10 на вопрос, до 40 символов —
   подходит?
2. **Куратор** читает банк, но не правит (как курсы) — подходит?
3. **Редактор вопроса** — отдельный экран с «Сохранить» (не автосохранение) — подходит?
4. **Где банк** — вкладка «Вопросы» в конструкторе курса — подходит?
5. **Архив**: вопрос убирается из банка, но остаётся в прошлых попытках; вернуть из архива нельзя в 3.1 — подходит?
6. **Ревизии** до появления попыток (3.3) не используются, правка всегда на месте — подходит?

Ответы (2026-11-07): рекомендации одобрены по всем шести вопросам.

Утверждено: владелец, 2026-11-07.

| тесты | `modules/assessments/bank.test.ts` (6: цикл вопроса, схема типа, поиск/фильтры/сортировка/страницы, теги и лимиты, права, изоляция); `tests/e2e/question-bank.spec.ts` (2) со снимками |

Отступления от карточки:

- Колонка тега — `label`, не `name`: реестр проверок считает `name` возможными ПДн (`NOT_PII` — ядро); в API поле по-прежнему `name`.
- Ядро и ресурс-фреймворк не менялись. «Новый вопрос» — форма ресурса с выбором типа; её `submit` открывает экран вопроса
  (в ResourcePage нет кнопки-ссылки). Кэш списка общий у ресурса всех курсов — маршрут сбрасывает его при входе.
- Схема типа `single_choice` допускает пустую формулировку и пустые варианты (заготовка редактора проходит схему, это
  проверяет существующий тест) — экран вопроса не даёт сохранить такое сам (`emptyField`). Жёсткая проверка на сервере —
  вопрос владельцу к 3.2 (тип вопроса — продуктовая область, но тест фазы 1 закрепляет текущее поведение).
- Редактор типа берётся из реестра напрямую (`clientQuestion`), а не через `QuestionEditorHost`: хост не сообщает о
  неверных данных, а кнопке «Сохранить» это нужно.

Проверки: `pnpm check` — ok (api 186); e2e — 39/39 (в нескольких полных прогонах падали посторонние тесты куратора «открыть демо-курс» — см. открытый вопрос плана фазы 2; сценарии банка стабильны). Снимки светлой темы и 375px просмотрены.
