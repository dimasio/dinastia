# 3.3: блок «Тест» — настройки, попытки, таймер, проверка

Задача: [phase-3-assessments](../task.md) · Шаг: 3 — ждёт утверждения

## 1. Запрос

Источник — роадмап 3.3 «Блок `quiz`: настройки, попытки, таймер, перемешивание, показ ответов, серверная проверка».

Что сейчас:

- Банк вопросов (3.1), семь типов вопросов с проверкой `grade`, `toPublic`, `review`, `shuffle` (3.2), ядро вопросов
  (`kernel/questions`: `getQuestions`, `publicQuestion`, `gradeAnswer`, `reviewQuestion`, `updateQuestion`/`reviseQuestion`).
- Блоки урока (фаза 2): `defineBlock`, дочерние таблицы, публикация строками (`block_key` общий у черновика и
  публикации), плеер ученика (`learn.lessons.*`, доступ к уроку — `learning`), события, фоновые задачи.
- Модель теста уже описана в `domain.md` §1 и §3 («Тест»): `block_quiz`, `block_quiz_questions`, `block_quiz_tags`,
  `quiz_attempts`, `attempt_questions`, `attempt_question_items`, `quiz_answers`, `quiz_answer_items`; события
  `quiz.submitted`, `quiz.graded`.
- Нет: блока `quiz`, таблиц попыток, процедур прохождения, экрана теста, автосдачи по таймеру.
  `assessments.hasAnswers` (3.1) всегда `false` — правка вопроса с ответами пока не создаёт ревизию.

Нужно: преподаватель добавляет в урок тест (вопросы из банка, настройки); ученик проходит его в плеере, получает баллы и
результат «сдал/не сдал»; сервер проверяет, ведёт таймер и попытки. Завершение урока по результату теста — 3.6,
проверка `open_text` преподавателем — 3.5–3.6.

В конструкторе урока — редактор блока: настройки, выбор вопросов (поиск, теги), случайные по тегам; «Как увидит ученик» — карточка настроек | `web-screens`, `screen-design`, `ui-kit` |

Работа в **два коммита** одного пункта: (а) блок `quiz` — таблицы блока, редактор, выбор вопросов, ревизии при ответах; (б) попытки — таблицы и сервис
попыток, API `quiz.*`, экран прохождения, таймер и автосдача, e2e.

Ядро (`kernel/**`, `packages/ui/**`, хосты блоков, `define.ts`) **не трогаем**. Не хватит — запрос `docs/tasks/requests/…`.

Варианты:

- Хранение ответов: **(выбран)** реляционно по `domain.md`, как велит D-032; одна колонка JSON с ответом была бы проще, но
  противоречит решению владельца (JSONB — только непрозрачные данные);
- Где живёт панель теста в плеере: **(выбран)** в `features/learning` по типу блока; альтернатива — расширить хосты блоков
  (это ядро) — отложить, пока интерактивных блоков с API больше одного.

Что не трогаем: завершение урока по результату теста (3.6), проверка `open_text` преподавателем и очередь (3.5, 3.6),
аналитика результатов для преподавателя (фаза 4), экспорт, пересчёт баллов прошлых попыток при смене настроек.

Риски: правка `pass_score_pct` у блока не пересчитывает прошлые попытки (`passed` фиксируется при сдаче); публикация нового
варианта теста при активной попытке — попытка идёт по своему снимку; изменение числа попыток — действует на следующий старт.

## 3. Целевая спецификация

| Раздел `domain.md` | Было | Станет |
| --- | --- | --- |
| §1 модель теста | описана | появляется в БД (ответы — `quiz_answers`, `quiz_answer_items`, как описано) |
| §3 «Тест» | кратко | правила ниже |
| §3 «Банк вопросов» | ревизия «с 3.3» | `hasAnswers` = есть в снимках попыток; тогда правка — новая ревизия |

**Настройки теста (по умолчанию):** выбор вопросов — фиксированный список; попыток — без ограничения (0); проходной
балл — 60 %; время — без ограничения; перемешивать вопросы — нет; перемешивать варианты — нет; показывать верные ответы — после сдачи.

| Правило | Что |
| --- | --- |
| Старт | у зачисленного ученика, урок открыт; лимит попыток считает начатые попытки (завершённые и активную); есть активная — вернётся она; исчерпан лимит — `ATTEMPTS_EXHAUSTED` |
| Снимок | вопросы фиксируются при старте: ревизии, баллы, порядок вариантов; правка банка попытку не меняет |
| Перемешивание | «вопросы» — порядок вопросов; «варианты» — порядок вариантов у типов с выбором; у «порядка» и «соответствия» элементы перемешиваются всегда (хранимый порядок — это ответ) |
| Ответ | сохраняется сразу при выборе (обновление страницы не теряет); после срока и после сдачи — `ATTEMPT_EXPIRED` / `ATTEMPT_NOT_ACTIVE` |
| Сдача | сервер проверяет каждый вопрос, неотвеченный — 0 баллов; есть `open_text` — попытка `submitted` до ручной проверки (3.6), баллы автопроверяемых уже видны; иначе `graded`, `passed` по порогу |
| Показ ответов | «никогда» — только итог и «сдал / не сдал»; «после сдачи» — по каждому вопросу ответ ученика, верно/неверно, верный ответ и пояснение; «после успешной сдачи» — то же, но только сдавшему |
| Таймер | считает сервер; на экране — оставшееся время; по истечении попытка сдаётся автоматически |

| Экран | Что |
| --- | --- |
| плеер → блок «Тест» | карточка: число вопросов, проходной балл, время, попытки (использовано из лимита), лучший результат; «Начать» / «Продолжить» / «Попытки исчерпаны» |
| прохождение | вопросы списком (в одну колонку), прогресс «отвечено N из M», таймер (если есть), «Сдать» с подтверждением при неотвеченных; закрытие страницы не теряет ответы |
| результат | баллы, процент, «Сдал / Не сдал» (или «Ожидает проверки»), разбор по правилу показа, «Пройти ещё раз» (если есть попытки) |
| конструктор урока → редактор блока | настройки (попытки, проходной балл, время в минутах, перемешивание, показ ответов); «Какие вопросы»: «Выбрать вручную» (поиск, теги, порядок) или «Случайные по тегам» (теги и число) |
| телефон 375px | вопросы и результат — в одну колонку; таймер закреплён сверху |

### Вопросы владельцу

1. **Два коммита** одного пункта (блок и редактор; попытки и прохождение) — подходит?
2. **Выбор вопросов**: фиксированный список или случайные по тегам (любой из тегов), до 50 вопросов; архивные пропускаются,
   заменённые ревизией подменяются текущей — подходит?
3. **Ответы** храним реляционно по `domain.md` (D-032), по соглашению ключей ответа типа; одну JSON-колонку не используем —
   подходит?
4. **Попытки и значения по умолчанию**: без ограничения попыток, проходной 60 %, без таймера; одна активная попытка,
   лимит считает и начатые — подходит?
5. **Таймер**: считает сервер; ответы после срока запрещены, сдача после срока оценивает сохранённое; автосдача раз в
   минуту — подходит?
6. **Показ верных ответов**: «никогда» / «после сдачи» / «после успешной сдачи» (по умолчанию — после сдачи); при
   «никогда» ученик видит только итог — подходит?
7. **Перемешивание**: опции «вопросы» и «варианты»; «порядок» и «соответствие» всегда перемешиваются — подходит?
8. **Панель теста в плеере** — в `features/learning` по типу блока (хосты блоков, то есть ядро, не меняем); API — namespace
   `quiz`, право `assessments.attempt` у роли ученика — подходит?
9. **Не входит в 3.3**: завершение урока по результату теста (3.6), ручная проверка `open_text` (3.5–3.6) — подходит?
