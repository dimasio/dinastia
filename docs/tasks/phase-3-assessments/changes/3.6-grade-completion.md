# 3.6: завершение урока по результату и ручная проверка `open_text`

Задача: [phase-3-assessments](../task.md) · Шаг: 3 — ждёт утверждения

## 1. Запрос

Источник — роадмап 3.6 «Завершение урока по `grade`; ручная проверка `open_text` в попытках» и демо фазы 3: ученик проходит тест и
сдаёт ДЗ, куратор отправляет на доработку, ученик пересдаёт, куратор принимает — **урок завершён**.

Что сейчас:

- Плеер ученика (2.6): урок завершается по `completion_rule` — `view` (при открытии), `manual` (кнопка), `all_blocks` **равен `view`**
  («до блоков с ответами»). Блоки `quiz` и `assignment` объявляют `completion: 'grade'`, но на завершение урока не влияют: урок с
  тестом считается пройденным в момент открытия. Настроить правило урока в интерфейсе нельзя (поле есть в БД, экрана нет).
- Тест (3.3): попытка с вопросом `open_text` после сдачи — `submitted`, `passed` пусто, баллы автопроверяемых видны; проверять ответы
  некому и негде. Задание (3.4–3.5): очередь и экран проверки есть, решения — `accepted`/`needs_revision`/`rejected`.
- Доменная модель уже описывает: `block_progress` (`enrollment_id`, `lesson_id`, `block_key`, `status`, `score`, `max_score`,
  `completed_at`), у `quiz_answers` — `graded_by`, `feedback`.
- Права и область проверяющих (3.5): `assessments.review`, `reviewScope`.

Нужно: урок с тестом или заданием завершается, когда тест сдан, а работа принята; ответы `open_text` проверяет человек, и попытка
получает итог; завершение видно ученику сразу.

## 2. Архитектура

Работа в **два коммита**: (а) завершение урока по результату, (б) ручная проверка `open_text`, демо фазы.

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| Прогресс блоков | **миграция**: в `learning` таблица `block_progress` (`enrollment_id`, `lesson_id`, `block_key`, `status` `done`/`failed`, `completed_at`; уникально по тройке); у `quiz_answers` — `graded_by_member_id`, `feedback` (rich); для уроков — значение по умолчанию `completion_rule` становится `all_blocks` (только для новых уроков, существующие не меняются) | `db-schema`, `lms-learners` |
| Завершение урока | `learning/service.ts`: `recordBlockResult(ctx, { enrollmentId, lessonId, blockKey, done })` — пишет `block_progress` и пересчитывает урок: правило `all_blocks` — урок завершён, когда выполнены **все блоки с `completion: 'grade'`** (тест сдан, задание принято); остальные блоки (`none`, `view`) считаются выполненными при открытии урока; `view` и `manual` — как раньше. Вызывает `assessments` **синхронно в той же транзакции** (направление `assessments → learning`, без цикла): сдача и оценка попытки (`passed`), решение по заданию (`accepted`). Событие `lesson.completed` и пересчёт `progress_pct` — прежние (`markCompleted`/`recalcProgress`) | `lms-learners`, `events-automations` |
| Правила | тест выполнен при первой сдаче с `passed = true` и остаётся выполненным; задание — при `accepted`; `needs_revision` и `rejected` блок не выполняют; `rejected` — конечный: урок под `all_blocks` не завершится (сброс — фаза 4) | `lms-learners` |
| Настройка урока | `courses.lessons.update` (только `completionRule`, право `courses.manage`) и переключатель в шапке конструктора урока: «Урок считается пройденным: при открытии / когда выполнены задания и тесты / по кнопке»; куратор — только чтение | `api-endpoints`, `web-screens` |
| Ручная проверка | модуль `assessments`: **очередь проверки** получает строки теста — одна на попытку в статусе `submitted` (ждёт проверки) и `graded` (оценена); `ReviewRow.kind` (`assignment` / `quiz`), статус `graded`, фильтр «Тип»; список — `UNION ALL` двух источников; **экран проверки попытки** `/admin/review/attempts/$attemptId`: ученик, тест, ответы `open_text` (с текстом ученика) и справка по автопроверенным; для каждого вопроса — баллы (0…максимум, шаг 0,5) и комментарий; «Сохранить оценки» (можно частично); когда оценены все `open_text`, попытка становится `graded`: итог = автопроверка + ручные баллы, `passed` по порогу, событие `quiz.graded`, `recordBlockResult` | `lms-assessments`, `admin-resource` |
| Ученику | в результате попытки баллы и комментарий за `open_text` видны **всегда** (это оценка проверяющего, а не верный ответ), остальной разбор — по правилу показа ответов; «Ждёт проверки» сменяется итогом; письмо о результате ручной проверки теста не шлётся; плеер обновляет статус урока сразу после сдачи, решения и оценки (инвалидация запросов) | `web-screens` |
| Контракт API | **добавление**: `review.list` — `kind`, фильтр `kind`, статус `graded`; `review.attempt` (попытка целиком для проверки), `review.gradeAttempt` (оценки вопросов: `[{ attemptQuestionId, score, feedback }]`); `quiz.result` — баллы и комментарии за ручные вопросы; `courses.lessons.update` | `api-endpoints` |
| Права | `assessments.review` (admin, teacher, curator); область — `reviewScope` (до потоков — вся школа) | `permissions` |
| Демо фазы 3 | `tests/e2e/phase-3.spec.ts`: преподаватель собирает урок с тестом (с `open_text`) и заданием, публикует; ученик проходит тест, сдаёт задание; куратор оценивает ответ `open_text`, возвращает задание на доработку, принимает после пересдачи; урок у ученика — «пройден», прогресс курса — 100 % | `testing` |
| Тесты | интеграционные: завершение урока по `all_blocks` (только тест / только задание / оба; тест не сдан, сдан без зачёта, сдан с зачётом; задание принято, на доработке, отклонено), `view` и `manual` без изменений, урок без `grade`-блоков под `all_blocks` завершается при открытии; ручная оценка (баллы, пределы, частичное сохранение, итог и `passed`, события, повторная оценка запрещена после `graded`?), права и область, очередь с двумя видами строк, фильтры; unit: расчёт завершения; e2e — `phase-3.spec.ts`, `lesson-completion` | `testing` |

Ядро (`kernel/**`, `packages/ui/**`, хосты блоков) **не трогаем**.

Что не трогаем: сброс отклонённой работы и повторная сдача по решению преподавателя (фаза 4); флаг `is_required` блока и его экран
(все `grade`-блоки считаются обязательными); настройки доступа к урокам и дрип в интерфейсе (фаза 4); письма о результате
теста; оценка задания баллами; аналитика результатов.

Риски: ученик с **отклонённой** работой не завершит урок под `all_blocks` (и не пройдёт последовательный курс) — осознанное
ограничение до фазы 4; смена `completion_rule` у урока с прошлыми результатами не пересчитывает завершённость ретроспективно
(пересчёт — при следующем событии блока или открытии урока); оценка `open_text` пересчитывает итог попытки — переоценка после
`graded` в 3.6 запрещена (`ATTEMPT_STATE`).

## 3. Целевая спецификация

| Раздел `domain.md` | Было | Станет |
| --- | --- | --- |
| §1 `block_progress`, `quiz_answers.graded_by`/`feedback` | описаны | появляются в БД (`block_progress` — в `learning`, статус только `done`/`failed`) |
| §3 «Завершение урока» | `all_blocks` = `view` до фазы 3 | `all_blocks` — выполнены все блоки `grade` (тест сдан с зачётом, задание принято), остальные — при открытии; по умолчанию у новых уроков |
| §3 «Тест» | `submitted` до ручной проверки (3.6) | ручная оценка: баллы 0…максимум, комментарий; итог и `passed` после оценки всех ручных вопросов |

| Правило | Что |
| --- | --- |
| Тест выполнен | первая сдача с `passed = true` (автоматически или после ручной оценки); неудачные попытки блок не снимают |
| Задание выполнено | статус `accepted` (в том числе автопринятие без проверки); `rejected` — блок не выполнен |
| Урок завершён (`all_blocks`) | все `grade`-блоки опубликованной версии выполнены; без таких блоков — при открытии |
| Урок завершён (`view`, `manual`) | как раньше: при открытии / кнопкой |
| Ручная оценка | проверяющий задаёт баллы каждому `open_text` (0…`points`, шаг 0,5) и комментарий; сохранять можно частями; когда оценены все — попытка `graded` |
| Что видит ученик | итог попытки; за ручные вопросы — свои баллы и комментарий проверяющего; верные ответы и пояснения — по правилу показа ответов |

| Экран | Что |
| --- | --- |
| `/admin/review` | очередь с видами «Задание» и «Тест»; у теста статус «Ждёт проверки» / «Оценён»; фильтры «Тип», «Статус», «Курс», поиск |
| `/admin/review/attempts/$attemptId` | шапка (ученик, курс, урок, тест, баллы автопроверки); ответы `open_text` с полями «Баллы» и «Комментарий» и подсказкой максимума; «Сохранить оценки»; итог и «Сдал / Не сдал» после завершения; на телефоне — одна колонка |
| конструктор урока | переключатель «Урок считается пройденным» в шапке (куратор — текст) |
| плеер | «Урок пройден» появляется сразу после зачёта теста или принятия задания (без перезагрузки) |

### Вопросы владельцу

1. **Два коммита** (завершение урока; ручная проверка и демо) — подходит?
2. **Завершение по `all_blocks`**: все блоки `grade` обязательны (тест сдан с зачётом, задание принято), остальные блоки — при открытии;
   отдельного признака «обязательный блок» не вводим — подходит?
3. **Правило урока**: переключатель в конструкторе урока (при открытии / по заданиям и тестам / по кнопке); у **новых** уроков по
   умолчанию «по заданиям и тестам», существующие не меняются — подходит?
4. **`rejected`** — блок не выполнен, урок под `all_blocks` не завершится (сброс — фаза 4); неудачные попытки теста выполненный тест не
   снимают — подходит?
5. **Связь модулей**: `assessments` вызывает `learning.recordBlockResult` синхронно в той же транзакции (не событием) — подходит?
6. **Ручная проверка**: оценка баллами 0…максимум (шаг 0,5) и комментарий; сохранение частями; когда оценены все ручные вопросы —
   попытка `graded`; переоценка после этого не допускается — подходит?
7. **Очередь**: тесты — строки той же очереди (по одной на попытку), статусы «Ждёт проверки» / «Оценён», фильтр «Тип» — подходит?
8. **Ученику**: баллы и комментарий за ручные вопросы видны всегда, остальное — по правилу показа ответов; писем о результате
   теста нет — подходит?
