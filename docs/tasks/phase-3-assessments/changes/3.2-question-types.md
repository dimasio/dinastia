# 3.2: типы вопросов

Задача: [phase-3-assessments](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап 3.2: «`single_choice`, `multiple_choice`, `text_input` (точный/по шаблону), `number`, `ordering`,
`matching`, `open_text` (ручная проверка)». Из них `single_choice` есть (1.4); добавляются шесть.

Что сейчас:

- Реестр `@dinastia/questions` (`defineQuestion`) и ядро (`kernel/questions`: хранение, ревизии, `gradeAnswer`,
  `publicQuestion`, `reviewQuestion`) готовы; банк вопросов курса и экран вопроса подхватывают типы из реестра сами
  (тип в списке и в выборе при создании — без правок экрана).
- Общие таблицы вопросов уже хранят всё нужное: колонки `scoring` (`all_or_nothing`/`partial`), `case_sensitive`,
  `number_answer`, `number_tolerance`; виды элементов `option`, `order_item` (`correct_position`), `match_left`/`match_right`
  (`match_key`), `accepted_text` — **миграция не нужна** (скилл `question-types`).
- Схема `single_choice` допускает пустую формулировку и пустые варианты (заготовка редактора проходит схему, это
  закреплено тестом фазы 1); экран банка (3.1) не даёт сохранить такое сам.

Нужно: преподаватель составляет вопросы шести новых типов; каждый тип умеет показать вопрос ученику без верных
ответов, проверить ответ на сервере и показать разбор. Прохождение (попытки, блок `quiz`) — 3.3.

## 2. Архитектура

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| Типы | шесть пакетов в `packages/questions/src/<тип>/` (`pnpm gen:question <тип>` для каждого): `definition.ts` (`defineQuestion`: схема, `toPublic`, `responseSchema`, `grade`, `review`, `shuffle`), `editor.tsx`, `viewer.tsx`; регистрация в реестрах, иконки, строки `questions:<тип>.*` | `question-types` |
| Правила проверки | см. таблицу §3; `grade` — чистые функции без случайности и времени, баллы ∈ [0, max], частичный балл только по `scoring: partial` | `question-types` |
| Секреты | `toPublic` убирает верные ответы и пояснение; у `ordering` — исходный порядок элементов не раскрывает верный (порядок в `toPublic` задаёт сервер, 3.3); у `matching` — пары не раскрыты (правые части отдельным списком); `defineQuestion` и `check:registries` проверяют по `example()` | `security-baseline` |
| Банк (3.1) | без правок: тип появляется в выборе при создании, в фильтре и в колонке «Тип» (`assessments:questions.values.type.<тип>` — подписи типов в строках) | `i18n` |
| БД | **миграции нет**; допуск: шаблон `text_input` — подстановки в самом допустимом ответе (без новой колонки) | `db-schema` |
| Ядро | не меняется (`kernel/questions` работает по контракту типа); механика реестра — не трогаем | — |
| Тесты | на каждый тип: верный, неверный, частичный, пустой ответ, `toPublic` без секретов, схема (граничные случаи); отрисовка редактора и просмотров (в попытке и в разборе); e2e: `tests/e2e/question-types.spec.ts` — банк: по одному вопросу каждого типа → предпросмотр → ответ → разбор в песочнице `/dev/questions` (расширяется выбором типа) | `testing` |

Что не трогаем: попытки, снимки, таймер, блок `quiz` (3.3); ручная проверка `open_text` преподавателем и очередь (3.5, 3.6);
банк вопросов и теги (3.1); перетаскивание в `matching` (выбор из списка достаточен; dnd — позже по запросу).

Риски: правка проверки существующего типа меняет баллы сданных попыток — здесь все типы новые, пересчёта нет;
шаблоны `text_input` с подстановками — без регулярных выражений (нет ReDoS, нет «магии» для преподавателя).

## 3. Целевая спецификация

| Тип | Что составляет преподаватель | Что видит ученик | Проверка (`grade`) | Частичный балл (`scoring: partial`) |
| --- | --- | --- | --- | --- |
| `multiple_choice` (несколько верных) | формулировка, 2–20 вариантов, ≥1 верный и ≥1 неверный, баллы, режим | флажки; число верных не сообщается | верно, если выбраны ровно верные | `баллы × max(0, (верно выбранные − лишние) / всего верных)` |
| `text_input` | формулировка, допустимые ответы (1–20 строк до 200 символов), «учитывать регистр» (по умолчанию нет) | поле ввода | совпадение с любым допустимым после нормализации: пробелы по краям убраны, подряд идущие схлопнуты, `ё`=`е`, регистр — по настройке; в допустимом ответе `*` — любая последовательность, `?` — один символ | нет (всё или ничего) |
| `number` | формулировка, верное число, допуск (≥ 0, по умолчанию 0) | поле числа (запятая и точка — десятичный разделитель) | `|ответ − верное| ≤ допуск` | нет |
| `ordering` | формулировка, 2–10 элементов в верном порядке | список в перемешанном порядке, кнопки «Выше/Ниже» (клавиатура) | верно, если порядок полностью совпал | доля элементов на своих местах |
| `matching` | формулировка, 2–10 пар «левое — правое» | левые части, у каждой выбор правой из списка (список перемешан) | верно, если все пары верны | доля верных пар |
| `open_text` | формулировка, образец ответа (пояснение, не показывается ученику) | многострочное поле, до 5000 символов | **ручная** (`manual`): ответ ждёт проверяющего (3.6), `gradeAnswer` → `null` | — |

Все типы: баллы 1–100 (как у `single_choice`), пояснение к ответу необязательно; разбор (`review`) показывает верный ответ
и пояснение — только по правилу `show_correct` блока `quiz` (3.3).

**Ужесточение схемы (вопрос 7).** Пустая формулировка и пустые варианты/элементы — ошибка схемы для **всех** типов,
включая `single_choice`: коды `PROMPT_REQUIRED`, `OPTION_REQUIRED`, `ITEM_REQUIRED` (текст — `questions:errors.*`). Заготовка
редактора по-прежнему может не проходить схему. Существующий тест `single_choice` «заготовка редактора проходит схему»
меняется на «заготовка не проходит схему: нужна формулировка» — это сознательное изменение контракта, ждёт вашего решения;
экранная проверка 3.1 (`emptyField`) становится не нужна и убирается.

| Экран | Что |
| --- | --- |
| экран вопроса (3.1) | редактор выбранного типа; тип показывается в выборе по названию (`questions:<тип>.title`); без изменений кода |
| песочница `/dev/questions` | выбор типа; пройти и проверить любой тип в браузере (проверка — ради демо, в продукте только сервер) |
| телефон 375px | все просмотры и редакторы — в одну колонку, элементы не меньше 44 px по высоте |

### Вопросы владельцу

1. **Частичный балл** — только у `multiple_choice`, `ordering`, `matching` по формулам таблицы; режим выбирает автор
   вопроса, по умолчанию «всё или ничего» — подходит?
2. **`text_input`**: допустимые ответы + регистр + нормализация (пробелы, `ё`=`е`) + шаблон с `*` и `?` (без регулярных
   выражений) — подходит?
3. **`number`**: допуск абсолютный (не процент); запятая и точка принимаются — подходит?
4. **`ordering`**: «Выше/Ниже» кнопками (мышь и клавиатура), без перетаскивания — подходит?
5. **`matching`**: у каждой левой части выбор правой из списка, до 10 пар, лишних правых нет — подходит?
6. **`open_text`**: до 5000 символов, образец ответа — в «пояснении», ученику не показывается до разбора — подходит?
7. **Ужесточение схемы** (пустая формулировка/варианты — ошибка для всех типов, включая `single_choice`; тест фазы 1
   «заготовка проходит схему» заменяется) — подходит?
8. **Порядок работы**: один пункт 3.2, но два коммита — «выбор и ввод» (`multiple_choice`, `text_input`, `number`) и
   «порядок и пары» (`ordering`, `matching`, `open_text`) — подходит?

Ответы (2026-11-08): рекомендации одобрены по всем восьми вопросам.

Утверждено: владелец, 2026-11-08.

## 4. Разработка

| Что | Где |
| --- | --- |
| типы | `packages/questions/src/{multiple_choice,text_input,number,ordering,matching,open_text}/` — `definition.ts`, `editor.tsx`, `viewer.tsx` (заготовки — `pnpm gen:question`, реестр и иконки — у маркеров) |
| общее | `common.ts` (`PromptText`, `requiredCompact`, `Points`, `Scoring`, `shuffled`, `normalizeText`, `matchesPattern`, `roundScore`), `shared.tsx` (`EditorFrame` — формулировка, баллы, режим, пояснение; `ViewerFrame`) |
| схема строже | `single_choice` и новые типы: `PROMPT_REQUIRED`, `OPTION_REQUIRED`, `ITEM_REQUIRED`; экранная проверка `emptyField` (3.1) убрана |
| веб | песочница `/dev/questions` — выбор типа; предпросмотр в банке — временные id элементов (`features/assessments/temp-ids.ts`) |
| строки | `questions:<тип>.*`, `questions:scoring.*`, коды ошибок схемы; `assessments:questions.values.type.*` |
| тесты | `packages/questions/src/types.test.tsx` (33: проверка каждого типа — верный, неверный, частичный, пустой; граница допуска; шаблоны; схема; `toPublic` без секретов и без раскрытия порядка; отрисовка просмотров в попытке и разборе); `tests/e2e/question-types.spec.ts` (8) со снимками |

Отступления от карточки:

- Один коммит вместо двух («выбор и ввод», «порядок и пары»): общие файлы (реестры, строки, `common.ts`) делились между
  группами, к моменту разбиения всё было готово и проверено целиком.
- Существующие тесты, затронутые решением 7: `questions.test.tsx` — «заготовка редактора проходит схему» заменён на
  «заготовка схему не проходит»; e2e `questions.spec` «без верного варианта» — точное совпадение текста ошибки заменено на
  «содержит» (теперь вместе с ней показываются ошибки пустой формулировки и вариантов).
- Редактор `matching` держит пары рядом: i-я левая и i-я правая части связаны общим `matchKey` (случайный UUID).
- `ordering`: показанный ученику порядок фиксируется как ответ сразу при показе (чтобы «не трогал» не значило «не
  ответил»); если в 3.3 понадобится иное — менять там.

Проверки: `pnpm check` — ok (questions 46, api 186); e2e — 47/47. Снимки просмотрены (телефон, порядок).
