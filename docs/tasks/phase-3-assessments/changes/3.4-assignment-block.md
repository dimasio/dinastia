# 3.4: блок «Домашнее задание» — сдача, статусы, повторная отправка

Задача: [phase-3-assessments](../task.md) · Шаг: 6 — готово

## 1. Запрос

Источник — роадмап 3.4 «Блок `assignment`: формулировка, ответ текстом и файлами, статусы, повторная отправка».

Что сейчас:

- Блоки урока (фаза 2): `defineBlock`, публикация строками с общим `block_key`, редактор блока, плеер ученика; блок `quiz`
  (3.3) показал приём «панель блока в плеере — компонент приложения, API по `lessonId` и `blockKey`».
- Файлы школы (`files-media`): назначение файла с правом и лимитами, загрузка напрямую в S3 по подписанной ссылке, привязка
  только готового файла своего назначения, загруженного этим участником; ссылки на чтение — подписанные.
- Форматированный текст (`rich-text`): профили, редактор, просмотр, `collectFileIds`.
- Модель задания описана в `domain.md` §1 и §3: `block_assignment`, `submissions`, `submission_files`, `submission_comments`;
  статусы `draft → submitted → (needs_revision → submitted)* → accepted | rejected`; после `accepted` блок выполнен.
- Нет: блока `assignment`, таблиц сдач, процедур, экрана ученика, перехода статусов.

Нужно: преподаватель добавляет в урок задание (формулировка, что принимать: текст и/или файлы); ученик пишет ответ, прикладывает
файлы, отправляет, при доработке отправляет снова; преподаватель принимает, возвращает на доработку или отклоняет.
Очередь проверки, экран проверки с перепиской и куратор — 3.5; завершение урока по принятому заданию — 3.6.

Один коммит (объём меньше 3.3).

Ядро (`kernel/**`, `packages/ui/**`, хосты блоков) **не трогаем**. Не хватит — запрос `docs/tasks/requests/…`.

Что не трогаем: очередь проверки, экран проверки, ответы ученика в переписке и файлы к комментариям, куратор и его область, письма
(3.5); завершение урока по принятому заданию (3.6); оценка баллами; антиплагиат, взаимопроверка (вне MVP).

Риски: файл остаётся в хранилище после снятия со сдачи (как в 2.7 — очистка сирот отдельной задачей); правка настроек блока
(`max_files`, запрет текста) не меняет уже отправленные сдачи; сдача хранит одну запись и `revision` — прежние версии текста
остаются только в комментариях проверяющего (история версий — отдельное изменение, если понадобится).

## 3. Целевая спецификация

| Раздел `domain.md` | Было | Станет |
| --- | --- | --- |
| §1 `submissions` | `…`, `grade` | + `revision`; `grade` не добавляется (оценки баллами нет, 3.4) |
| §3 «Домашнее задание» | статусы | правила ниже |

**Настройки задания (по умолчанию):** принимается текст и файлы, до 3 файлов, проверка преподавателем обязательна.

| Правило | Что |
| --- | --- |
| Ответ | текст (форматированный) и/или файлы — по настройкам блока; хотя бы одно непустое; файлов — не больше `max_files` |
| Черновик | ученик сохраняет ответ сколько угодно; видит только он; файлы привязываются сразу |
| Отправка | `draft → submitted` (или `needs_revision → submitted`, `revision` растёт); при `requires_review = false` — сразу `accepted` |
| Проверка | преподаватель: принять, вернуть на доработку (нужен комментарий), отклонить (нужен комментарий); `rejected` и `accepted` — конечные |
| Ученик и статусы | правит и отправляет только в `draft` и `needs_revision`; в `submitted`, `accepted`, `rejected` — только чтение |
| Комментарии | ученик видит комментарии проверяющего к своей сдаче; отвечать ученик начнёт в 3.5 |
| Доступ | как к уроку: открыт и зачислен (`LESSON_LOCKED`, `LESSON_NOT_FOUND`); задание, убранное из урока, — недоступно |

| Экран | Что |
| --- | --- |
| плеер → блок «Задание» | формулировка; плашка статуса («Черновик», «На проверке», «Нужна доработка», «Принято», «Отклонено»); форма ответа; «Сохранить черновик», «Отправить» (с подтверждением: после отправки править нельзя); комментарии проверяющего |
| конструктор урока → редактор блока | формулировка (форматированный текст), «Принимать текст», «Принимать файлы» и число файлов, «Проверяет преподаватель»; замечания «нет формулировки», «не выбрано, что принимать» |
| телефон 375px | форма и файлы — в одну колонку, кнопки на всю ширину |

### Вопросы владельцу

1. **Один коммит** для 3.4 (блок, сдачи, статусы, панель в плеере) — подходит?
2. **Ответ**: форматированный текст и/или файлы по настройкам блока; файлов до 10 (по умолчанию 3), типы — картинки, PDF, Word,
   Excel, PowerPoint, ZIP, TXT, CSV, MP3, MP4, до 100 МБ — подходит?
3. **Без проверки**: `requires_review = false` — при отправке сразу «принято» — подходит?
4. **Статусы и права ученика**: правит и отправляет в `draft` и `needs_revision`; `rejected` и `accepted` — конечные (после
   «отклонено» пересдать нельзя) — подходит?
5. **Одна запись** на ученика и блок, счётчик отправок `revision`; прежние версии текста не хранятся — подходит?
6. **Проверка в 3.4**: процедура `assignment.review` (принять / на доработку / отклонить + комментарий) для `admin` и `teacher`;
   очередь, экран и куратор — 3.5 — подходит?
7. **Комментарии проверяющего** хранятся в `submission_comments` и видны ученику; ответы ученика и файлы к комментариям — 3.5 —
   подходит?
8. **Письма ученику** о результате проверки — вместе с экраном проверки в 3.5; в 3.4 только события — подходит?
9. **Оценка**: только «принято / на доработку / отклонено», без баллов; колонку оценки не добавляем — подходит?
10. **Имена**: API `assignment` (REST `/assignment/...`), права `assessments.submit` (ученик) и `assessments.review` (admin,
    teacher), назначение файла `assessments.submission-file` — подтвердите.

Ответы (2026-11-08): рекомендации одобрены по всем десяти вопросам.

- Файл, снятый со сдачи, остаётся в хранилище (как в 2.7): очистка сирот — отдельной задачей.
- Заготовки блока генерировались `pnpm gen:block … --no-migration`, миграция — одна общая (`block_assignment` и таблицы сдач).
- Проверка работы в e2e — через API (`assignment.review`): экрана проверки до 3.5 нет.
- Урок с заданием, как и с тестом, пока завершается по правилу урока (`view` — при открытии); завершение по принятой работе — 3.6.
