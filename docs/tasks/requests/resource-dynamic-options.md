# Ресурс-фреймворк: варианты выбора из данных (значение + подпись)

**Задача, которая ждёт:** [4.2 — потоки](../phase-4-learners/changes/4.2-groups.md): вкладка «Ученики» — фильтр «Поток», выбор потока
при зачислении и в действии «Перевести в поток».

**Что нужно:** в `packages/ui/src/resource` — варианты фильтра и поля `select` с подписью из данных, а не из i18n:

```ts
filters: [{ field: 'groupId', options: groups.map((g) => ({ value: g.id, label: g.title })) }]
fields: { groupId: { widget: 'select', options: [{ value: '', label: t('groups.none') }, ...groupOptions] } }
```

`options: readonly (string | { value: string; label: string })[]` в `FilterDef` и `FieldOverride`; строка — как сейчас (подпись из i18n),
объект — подпись как есть (проверка ключей `keys.ts` его пропускает). `toListInput` сравнивает по `value`.

**Зачем:** выбор сущности школы (поток, курс, куратор, тег) в фильтре и форме ресурса — значения известны только во время работы.

**Что пробовал:** `labels` с `defaultValue` показывает сам id; подпись из i18n по id нельзя без `addResourceBundle` на лету (обход
ядра); свой фильтр снаружи `ResourcePage` не попадает в `toListInput` и ключ кэша списка.

**Сделано (2026-11-10, владелец разрешил править ядро):** `OptionDef = string | { value, label }` и `optionValue` в
`packages/ui/src/resource`; фильтр «Поток», выбор потока при зачислении и «Перевести в поток» — в `enrollments.ts`.

**Обходилось так:** колонка «Поток» — своим рендером; фильтр, выбор потока при зачислении и перевод — ждут запроса.
Вкладка «Потоки» сделана своими компонентами (`packages/ui`), без ресурса: ей нужен ещё и множественный выбор кураторов.
