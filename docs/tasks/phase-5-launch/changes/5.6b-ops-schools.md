# 5.6б: школы в консоли — метрики, список, карточка; поиск человека; журнал консоли

Задача: [phase-5-launch](../task.md) · Спека: [ops.md](../../../specs/ops.md) (§2 сценарии 2, 3, 5; §7 экраны 1–4) · Шаг: готово

## 1. Запрос

После 5.6а в `/ops` только создание школы. Нужно: оператор видит все школы с метриками, открывает карточку школы, находит человека
по почте, смотрит журнал своих действий. Утверждено владельцем 2026-11-11 (спека и план).

## 2. Архитектура

| Слой | Что | Скилл |
| --- | --- | --- |
| БД | `school_stats` (глобальная, PK `school_id` → `schools` каскад): `students`, `active_students_30d`, `courses`, `storage_bytes`, `owner_email` (ПДн), `last_activity_at`, `updated_at` | `db-schema` |
| Задача | `ops.school-stats` (модуль `ops`, `all-schools`, раз в час): пересчёт в транзакции школы (под RLS) и upsert строки | `background-jobs` |
| Контракт | `ops.schools.list` (поиск по названию/адресу/почте владельца, статус, сортировка), `ops.schools.get` (живые метрики, сотрудники, журнал консоли по школе), `ops.people.find` (точная почта → школы и роли через политику «свои членства»), `ops.audit.list` | `api-endpoints` |
| Журнал | `ops.person.searched` (только id найденного), `ops.school.viewed` не пишем (шум) | `security-baseline` |
| Веб | лэйаут `/ops` с меню «Школы · Люди · Журнал»; ресурсы `ops-schools`, `ops-audit`; карточка `/ops/schools/<id>`; «Создать школу» — диалог | `admin-resource`, `web-screens` |

Миграция: только добавление (`school_stats`). Ученики в метриках — без удалённых; активные — открывали урок за 30 дней.

## 3. Целевая спецификация

`ops.md` §3 (`school_stats`), §7 — утверждено.
