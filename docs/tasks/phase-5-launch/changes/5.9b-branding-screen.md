# 5.9б: экран «Оформление» — загрузка логотипа, цвета с проверкой контраста, предпросмотр, сброс

Задача: [phase-5-launch](../task.md) · Спека: [branding.md](../../../specs/branding.md) (§2 сценарии 1–5, §5 правила 2 и 7, §7) · Шаг: готово

## 1. Запрос

После 5.9а тема из БД применяется везде, но школа не может её поменять. Нужно: раздел «Оформление» в настройках.

## 2. Архитектура

| Слой | Что | Скилл |
| --- | --- | --- |
| Контракт | `schools.branding.get` / `update` (`BrandingView`, `BrandingUpdate`: тема целиком, файлы по отдельности); `previewTokens` — все токены одной темы для предпросмотра поверх текущей | `api-endpoints` |
| Сервис | `updateBranding`: контраст основного цвета (`BRANDING_LOW_CONTRAST` с `suggestion`), файл — готовый и своего назначения, прежний удаляется, `version + 1`, журнал `schools.branding.updated` с полями; запрещено при входе «от имени» | `security-baseline` |
| Веб | раздел «Оформление» на `/admin/settings` (виден с `schools.branding.manage`): логотип и значок вкладки — `ImageInput`, сохраняются сразу; цвета (палитра + `#rrggbb`), шрифт, скругления, тема по умолчанию — кнопкой «Сохранить»; предпросмотр светлой и тёмной темы; «Сбросить к теме Dinastia»; после сохранения CSS темы и фавикон перечитываются без перезагрузки | `admin-resource`, `ui-kit` |

Отличия от черновика спеки (поправлено в `branding.md`): раздел — карточка на странице настроек, а не вкладка (страница настроек — разделы
подряд); доменного события `branding.updated` нет — подписчиков нет, достаточно журнала.

шрифт, сохранение без перезагрузки, логотип в шапке, 375px без горизонтальной прокрутки, сброс). Снимки — светлая и 375px.
