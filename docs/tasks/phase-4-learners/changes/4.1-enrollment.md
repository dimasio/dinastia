# 4.1: зачисление, ссылки и приглашения, сроки и отзыв доступа

Задача: [phase-4-learners](../task.md) · Шаг: готово — (а) и (б)

## 1. Запрос

Источник — роадмап 4.1 «Модуль `learning`: зачисление (вручную, по приглашению, по ссылке), сроки доступа, отзыв доступа».

Что сейчас:

- `learning` (фаза 2–3): `enrollments` (`member_id`, `course_id`, `status` `active`/`completed`/`expired`/`revoked`, `source`
  `manual`/`invite`/`link`, `enrolled_at`, `expires_at`, `completed_at`, `progress_pct`; одно действующее на пару «участник — курс»),
  `lesson_progress`, `block_progress`, внутренняя `enrollMember` (идемпотентна; курс опубликован; срок из `courses.access_days`).
  Экранов и API зачисления **нет** — зачисляют сид и команда `src/enroll.ts`.
- Плеер: просроченный доступ — «Доступ закончился» (`ENROLLMENT_EXPIRED`), отозванное зачисление для ученика — как отсутствующее.
- Сотрудники школы приглашаются письмом со ссылкой `/invite/<token>` (`schools`): хэш токена, вход по magic link (`SignInForm`),
  принять может только владелец email. Страница `InvitePage`, письмо `schools.invitation`.
- Курс: `courses.access_days` есть в схеме и в `courses.update`, но в интерфейсе не настраивается.
- Домен: `enrollment_invites` (ссылки-приглашения курса: `token`, `expires_at`, `max_uses`, `uses`), `learning.expire-enrollments`.

Нужно: сотрудник зачисляет ученика (по почте), создаёт ссылку-приглашение на курс или шлёт приглашение на почту; ученик принимает
и попадает в курс; срок доступа настраивается и продлевается; доступ можно отозвать и вернуть.

## 2. Архитектура

Работа в **два коммита**: (а) зачисление, сроки, отзыв, экран «Ученики»; (б) приглашения — ссылка и письмо, страница `/join/<token>`.

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| БД | **миграция** (только добавление): `enrollments.revoked_at` и `invite_id`; `enrollment_invites` (`course_id`, `token` уникальный, `email` — для адресного приглашения, `expires_at`, `max_uses`, `uses`, `created_by_member_id`, `revoked_at`); составные ключи, RLS | `db-schema` |
| Права | `learning.read` — admin, teacher, curator (куратор до потоков видит всех, 4.2 — только свои); `learning.enroll` — admin, teacher (зачислять, продлять, отзывать, ссылки); `learning.study` — ученик (есть) | `permissions` |
| Зачисление | `enrollment.service.ts`: `enroll` по почте — **ученик школы** зачисляется сразу (источник `manual`, срок из `courses.access_days` или заданный), письмо «вас записали»; **незнакомая почта** — адресное приглашение (письмо со ссылкой, участник создаётся при принятии); сотрудник школы — `NOT_A_STUDENT`; заблокированный — `MEMBER_BLOCKED`; черновик и архив — `COURSE_NOT_PUBLISHED`; повтор по действующему — то же зачисление (идемпотентно); зачисление в статусе `revoked` — возвращает доступ | `data-access`, `lms-learners` |
| Сроки | срок по умолчанию — `courses.access_days` на момент зачисления; при зачислении можно задать свою дату; «Продлить» — новая дата или «без срока»; задача `learning.expire-enrollments` раз в сутки по всем школам переводит просроченные в `expired` (доступ ограничивается по дате и без неё — как сейчас) | `background-jobs` |
| Отзыв | «Отозвать доступ» — `revoked` (+ `revoked_at`, запись в журнал): ученик видит «Доступ отозван» и курс не открывает; прогресс сохраняется; «Вернуть доступ» — снова `active` с прежним прогрессом и сроком | `lms-learners` |
| Приглашения (б) | ссылка-приглашение курса: токен, срок (по умолчанию 30 дней), лимит использований (необязательно), отзыв; адресное — на почту, одно использование; принимает вошедший пользователь (вход по magic link, как у сотрудников): участник `student` создаётся при принятии, затем зачисление (источник `invite`/`link`); лимит и срок проверяются под блокировкой; сотрудник — `NOT_A_STUDENT`, заблокированный — `MEMBER_BLOCKED`; повторное принятие тем же человеком — без дубля | `integrations`, `security-baseline` |
| Письма | `learning.enrolled` (вас записали на курс, ссылка) и `learning.course-invitation` (приглашение со ссылкой `/join/<токен>`); адресное письмо шлёт задача (токен не лежит в очереди, как у сотрудников), письмо «зачислен» — подписчиком/задачей; остальные письма фазы — 4.8 | `notifications` |
| Контракт API | **добавление**: `learning.enrollments.list/enroll/extend/revoke/restore`, `learning.invites.list/create/revoke`, публичные `join.get` (сведения о приглашении) и `join.accept`; `learn.*` — код `ENROLLMENT_REVOKED` | `api-endpoints` |
| Веб | вкладка **«Ученики»** курса (`/admin/courses/$courseId/learners`, ресурс: ученик, почта, статус, источник, зачислен, срок, прогресс; поиск, фильтр статуса; действия «Продлить», «Отозвать», «Вернуть»), кнопка «Зачислить» (почта, срок), боковая панель «Ссылки-приглашения» (создать, копировать, отозвать), поле «Срок доступа по умолчанию, дней» (`courses.update`); публичная страница `/join/<token>` (б); плеер — «Доступ отозван» | `web-screens`, `admin-resource`, `screen-design` |
| Строки | `learning:*`, `emails:enrolled.*`, `emails:courseInvitation.*`, `errors:*` | `i18n` |
| Тесты | интеграционные: зачисление ученика школы / незнакомой почты / сотрудника / заблокированного / в черновик, идемпотентность, срок (по умолчанию курса, свой, продление, без срока), задача истечения, отзыв и возврат (доступ в плеере, прогресс), права (куратор читает, не зачисляет; ученик ничего), изоляция школ; приглашения (б): ссылка (срок, лимит, отзыв, повтор), адресное (чужая почта отказ), создание участника, письма; e2e `tests/e2e/enrollment.spec.ts`: преподаватель зачисляет, создаёт ссылку; ученик принимает по ссылке и открывает курс; отзыв и возврат; снимки | `testing`, `visual-review` |

Команда `src/enroll.ts` остаётся для сидов и e2e (теперь использует тот же сервис).

Ядро (`kernel/**`, `packages/ui/**`) **не трогаем**.

Что не трогаем: потоки и привязка к ним (4.2: `enrollments.group_id`), доступ к урокам по расписанию и экран его настройки (4.3), дедлайны (4.4),
кабинет ученика (4.5), аналитика и выгрузки (4.6), сертификаты (4.7), письма о дедлайнах, проверке и сертификате (4.8), оплата,
регистрация учеников без приглашения, массовый импорт учеников из файла.

Риски: ссылка-приглашение даёт доступ любому, у кого она есть, — срок, лимит и отзыв обязательны в интерфейсе, токен — 32 байта,
принятие ограничивается по частоте общим механизмом; почта ученика — персональные данные: список «Ученики» виден только
сотрудникам с `learning.read`, действия пишутся в журнал; заблокированный участник школы не может принять приглашение.

| Зачислить по почте | ученик школы — сразу; незнакомая почта — приглашение на почту; сотрудник — отказ; черновик/архив — отказ; повтор — то же зачисление; отозванное — возвращается |

### Вопросы владельцу

1. **Два коммита** (зачисление и экран; приглашения и `/join`) — подходит?
2. **Зачисление по почте**: ученик школы — сразу; незнакомая почта — приглашение на почту (аккаунт и участник создаются только после принятия, без согласия
   человека их не создаём); сотрудник — отказ — подходит?
3. **Ссылка-приглашение**: срок (30 дней по умолчанию), необязательный лимит, отзыв; принимает любой вошедший по magic link; сотрудник и заблокированный — отказ — подходит?
4. **Сроки**: по умолчанию из `courses.access_days` (задаётся на вкладке «Ученики»), своя дата при зачислении, продление, «без срока»; статус `expired` — задачей раз в сутки — подходит?
5. **Отзыв**: `revoked` сохраняет прогресс; «Вернуть доступ» — снова `active`; повторное зачисление отозванного — тоже возврат — подходит?
6. **Права**: `learning.read` (admin, teacher, curator; куратор до 4.2 — всех), `learning.enroll` (admin, teacher) — подходит?
7. **Письма** в 4.1: «вас записали» и «приглашение на курс»; остальные — в своих пунктах и 4.8 — подходит?
8. **Имена**: API `learning.enrollments.*`, `learning.invites.*`, публичные `join.*`, страница `/join/<токен>`, письма `learning.enrolled` и
   `learning.course-invitation`, таблица `enrollment_invites` — подтвердите.

## 4. Разработка

Решения владельца: «рекомендации одобряю»; затем **отступления от §3** — (1) «аккаунт создавать можно админам»: владелец и администраторы
создают аккаунт ученика при зачислении по незнакомой почте (вместо адресного приглашения вместо создания); (2) «приглашение по почте
оставь»: адресное приглашение на почту остаётся в части (б) — для преподавателя с незнакомой почтой (отказ `ONLY_ADMIN_CREATES_ACCOUNTS`
в (а) заменится приглашением).

**Часть (а) — готово.** Миграция `0020_enrollment_revoked` (`enrollments.revoked_at`); `learning.enrollments.list/enroll/extend/unlimit/revoke/restore`;
письмо `learning.enrolled`; задача `learning.expire-enrollments`; права `learning.read`/`learning.enroll`; вкладка «Ученики»
(`/admin/courses/$courseId/learners`) с полем «Срок доступа по умолчанию»; «Доступ отозван» у ученика. Тесты: api
`enrollment.test.ts` (10), e2e `enrollment.spec.ts`; снимки `test-results/screens/4.1-*.png`.

**Часть (б) — готово.** Миграция `0021_enrollment_invites` (таблица `enrollment_invites`, `enrollments.invite_id`); `learning.invites.list/create/revoke`,
публичные `join.get/accept`; письмо `learning.course-invitation` (токен выпускает задача); страница `/join/<токен>`; панель «Ссылки-приглашения».
`enroll` по незнакомой почте у преподавателя возвращает `invited` (у владельца и администратора — создаёт аккаунт). Тесты: api `invites.test.ts` (10),
e2e `enrollment.spec.ts` (ссылка с лимитом, исчерпанная ссылка, адресное приглашение).
