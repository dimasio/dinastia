# 4.2: потоки, кураторы потоков, ограничение куратора своими потоками

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.2 «Потоки/группы, кураторы групп, ограничение куратора своими группами».

Что сейчас:

- Спека (`docs/specs/domain.md` §1) уже называет таблицы `groups` (`course_id`, `title`, `starts_at`, `ends_at`, `access_days`),
  `group_curators` (`group_id`, `member_id`), поля `enrollments.group_id?` и `enrollment_invites.group_id?` — в коде их **нет**
  (`apps/api/src/modules/learning/schema.ts`). Роль `curator` по спеке (§2) — «проверка ДЗ и прогресс **только своих групп**».
  Глоссарий: «поток» (`group`) — набор учеников курса с общим стартом и кураторами; «группа», «когорта» — не использовать.
- Куратор сейчас видит **всех** учеников и все работы школы: `learningScope` (`apps/api/src/modules/learning/enrollment.service.ts:26`)
  и `reviewScope` (`apps/api/src/modules/assessments/review.service.ts:21`) возвращают `undefined`. `reviewScope` используют очередь
  проверки, карточка работы и ручная оценка тестов (`grading.service.ts:22`).
- Права: `learning.read` — admin, teacher, curator; `learning.enroll` — admin, teacher. Скилл `lms-learners` предусматривает
  `learning.groups.manage` (owner, admin, teacher) и политику `learning/policies.ts → groupScope(ctx)`.
- `tenantRef` не поддерживает `set null` (`packages/db/src/tenant.ts:73`) — при удалении потока зачисления отвязываются в сервисе.

Нужно: школа делит учеников курса на потоки, назначает потокам кураторов; куратор видит учеников и проверяет работы только своих
потоков; ученика можно зачислить сразу в поток, перевести в другой и пригласить ссылкой в поток.

## 2. Архитектура

Один коммит.

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| БД | **миграция** (только добавление) `0022_groups`: `groups` (`course_id`, `title`, `starts_at?`, `ends_at?`, `access_days?`), `group_curators` (`group_id`, `member_id`, уникально пара), `enrollments.group_id?`, `enrollment_invites.group_id?`; составные ключи `tenantRef` (`groups → courses` cascade, `group_curators → groups/members` cascade, `enrollments/enrollment_invites → groups` restrict), индексы `(school_id, course_id)`, `(school_id, group_id)`, `(school_id, member_id)` у кураторов; RLS | `db-schema` |
| Права | `learning.groups.manage` — admin, teacher (создать, изменить, удалить поток, назначить кураторов, перевести ученика); список потоков — `learning.read` | `permissions` |
| Политика | `learning/policies.ts → groupScope(ctx)`: для `curator` — `enrollments.group_id in (потоки, где он куратор)`, для остальных — без ограничения. `learningScope` и `reviewScope` вызывают её; запись вне области в `get` — `notFound` | `permissions`, `data-access` |
| Потоки | `groups.service.ts`: список потоков курса (название, старт, окончание, срок, учеников, кураторы), создание, изменение, удаление (зачисления и приглашения отвязываются, ученики остаются в курсе «без потока»); кураторы — участники школы со статусом «активен» и ролью сотрудника (не ученик), иначе `NOT_STAFF` | `data-access`, `lms-learners` |

| Приглашения | ссылка и адресное приглашение — необязательный поток; принявший попадает в него | `lms-learners` |
| Контракт API | **добавление**: `learning.groups.list/create/update/remove`, `learning.enrollments.move`; необязательный `groupId` в `enrollments.enroll`, `invites.create`; в `enrollments.list` — колонка «поток» и фильтр по потоку; в `invites.list` — поток | `api-endpoints` |
| Веб | вкладка **«Потоки»** курса (`/admin/courses/$courseId/groups`, ресурс: название, старт, окончание, срок, учеников, кураторы; форма — название, даты, срок доступа, кураторы); вкладка «Ученики» — колонка и фильтр «Поток», выбор потока при зачислении и в ссылке-приглашении, действие строки «Перевести в поток»; куратор: вкладка «Потоки» — только свои, без действий; «Ученики» и очередь проверки — только свои потоки | `admin-resource`, `web-screens`, `screen-design` |
| Журнал | `learning.group.created/updated/deleted`, `learning.group.curators-changed`, `learning.enrollment.moved` | `security-baseline` |
| Строки | `learning:groups.*`, `errors:GROUP_NOT_FOUND`, `errors:NOT_STAFF` | `i18n` |
| Тесты | интеграционные: CRUD потока и права (куратор и ученик не управляют), кураторы (ученик и заблокированный — отказ), удаление отвязывает, зачисление в поток и срок потока, перевод, ссылка в поток, **область куратора**: список учеников, очередь проверки, карточка работы (`notFound`), ручная оценка теста — только свои потоки; ученик без потока куратору не виден; изоляция школ; e2e `tests/e2e/groups.spec.ts`: преподаватель создаёт поток с куратором, зачисляет в него ученика; куратор видит только его и его работу; снимки (светлая, тёмная, 375px) | `testing`, `visual-review` |

Варианты:

- *Поток обязателен для каждого зачисления* — отвергнут: школа без потоков (самостоятельные курсы) работает как сейчас.
- *Куратор назначается на курс целиком* — отвергнут: спека и глоссарий — куратор потока.
- *Несколько потоков у одного зачисления* — отвергнут: поток — «общий старт», ученик курса в одном потоке.

Риски: ограничение куратора — граница доступа к ПДн учеников и их работам: одна политика `groupScope` на все места, тесты на каждое место
(список, очередь, карточка, оценка). Ученик без потока куратору не виден — школа должна это понимать (подсказка на вкладке «Потоки»).

Что не трогаем: drip от начала потока (4.3 — `starts_at` уже будет), дедлайны потока (4.4, `deadlines.group_id`), аналитика по потокам (4.6),
уведомления кураторам о новых работах (4.8 или позже), перенос прогресса между курсами, чат потока.

Ядро (`kernel/**`, `packages/ui/**`, `packages/db/**`) **не трогаем**.

| Правило | Что |
| --- | --- |
| Поток | принадлежит курсу; название обязательно; старт, окончание, срок доступа (дней) — необязательны; окончание — для информации, доступ не ограничивает |
| Кто управляет | `learning.groups.manage` — owner, admin, teacher; смотрит список — `learning.read` (куратор — только свои потоки) |
| Кураторы потока | любые активные сотрудники школы (не ученики); ограничение области действует только для роли `curator` |
| Ученик и поток | у зачисления не больше одного потока; можно без потока; перевод между потоками не меняет срок и прогресс |
| Срок | своя дата при зачислении → срок потока (от старта потока, если он ещё не наступил, иначе от зачисления) → срок курса |
| Удаление потока | ученики и ссылки остаются, «без потока»; кураторы снимаются |
| Приглашения | ссылка и адресное приглашение могут вести в поток |
| Куратор | видит учеников, работы и результаты тестов только учеников своих потоков; учеников без потока не видит |
| Журнал | создание, изменение, удаление потока, смена кураторов, перевод ученика |

| Экран | Что |

### Вопросы владельцу

1. **Поток необязателен**: ученик может быть без потока; у зачисления не больше одного потока — подходит?
2. **Куратор без потока**: ученики без потока и их работы куратору **не видны** (видят преподаватели и админы) — подходит, или куратор
   без назначенных потоков должен видеть всех, как сейчас?
3. **Кураторы потока** — любые сотрудники (не ученики); ограничение области — только у роли `curator` — подходит?
4. **Срок потока**: своя дата → `access_days` потока (от старта потока, если он впереди, иначе от зачисления) → срок курса; перевод в другой
   поток срок **не** пересчитывает; окончание потока доступ не ограничивает — подходит?
5. **Удаление потока** — разрешено; ученики остаются в курсе без потока — подходит (или только когда в потоке нет учеников)?
6. **Права**: `learning.groups.manage` — admin, teacher (как в скилле); куратор только смотрит свои потоки — подходит?
7. **Имена**: таблицы `groups`, `group_curators`; API `learning.groups.*`, `learning.enrollments.move`; вкладка «Потоки»
   `/admin/courses/$courseId/groups`; политика `groupScope` — подтвердите.

Утверждено: владелец, 2026-11-10 — «рекомендации одобряю» (все 7 ответов — по рекомендации §3).
