# 4.4: дедлайны уроков и напоминания

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.4 «Дедлайны уроков и напоминания».

Что сейчас:

- Спека (`domain.md` §1) называет таблицу `deadlines` (`course_id`, `group_id?`, `lesson_id`, `due_at` или `due_days` «от начала»); в коде
  её нет. Глоссарий: «дедлайн» (`deadline`) — срок сдачи урока/задания.
- Писем о сроках нет; из писем есть «вас записали», «приглашение на курс», «работа проверена». Транзакционные письма в целом —
  пункт 4.8, но письмо о дедлайне роадмап упоминает и там, и здесь.
- Расписание открытия уроков (4.3) уже считает «от начала» как **старт потока ученика или зачисление** (`learning/service.ts`
  `accessBase`), «с даты» — по Москве. Дедлайн естественно считать так же.
- Кабинет ученика со списком ближайших сроков — 4.5, аналитика (кто просрочил) — 4.6.

Нужно: преподаватель задаёт уроку срок, ученик видит его в оглавлении курса и получает напоминание до срока и после просрочки.

## 2. Архитектура

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| БД | **миграция** (только добавление): у урока — `lessons.deadline_days` (через N дней от старта потока/зачисления) и `lessons.deadline_date` (дата); таблица `deadline_reminders` (`enrollment_id`, `lesson_id`, `kind` `soon`/`overdue`, `sent_at`, уникально тройка) — чтобы каждое напоминание ушло один раз. Таблицу `deadlines` из спеки **не вводим** (см. варианты) | `db-schema` |
| Срок | `deadlineOf(lesson, base)`: дата — конец дня 23:59 по Москве; «через N дней» — конец дня (по Москве) даты «старт + N». Урок «просрочен», если срок прошёл, а урок не завершён. Мягкий дедлайн: **ничего не закрывает**, только показывается и напоминает | `lms-learners` |
| Контракт | **добавление**: `courses.lessons.update` — `deadlineDays`, `deadlineDate`; `Lesson` — те же поля; оглавление ученика (`OutlineLesson`) — `dueAt`, `overdue` | `api-endpoints` |
| Напоминания | задача `learning.deadline-reminders` раз в день в 10:00 по Москве по всем школам: ученикам действующих зачислений — «завтра срок» (срок в ближайшие сутки, урок не завершён) и «срок прошёл» (один раз на следующий день); отметка в `deadline_reminders` в той же транзакции. Письмо `learning.deadline-reminder` (курс, урок, срок, ссылка на урок; вариант «завтра» / «просрочено») | `background-jobs`, `notifications` |
| Веб | конструктор урока — «Срок сдачи»: нет / через N дней / до даты (рядом с «Когда урок открывается»); оглавление и плеер ученика — «Сдать до 12 декабря», просроченный — красным «Срок прошёл 12 декабря» | `web-screens`, `ux-writing` |
| Строки | `courses:deadline.*`, `learning:course.due*`, `emails:deadlineReminder.*`, `errors:*` | `i18n` |
| Тесты | unit `deadlineOf` (поток, дата по Москве, конец дня); интеграционные: настройки урока и права, оглавление (`dueAt`, `overdue`), задача — кому уходит и не уходит (завершён урок, отозван/истёк доступ, уже напомнили, не наступило), один раз на вид, изоляция школ; e2e `deadlines.spec.ts`: преподаватель ставит срок, ученик видит «Сдать до …»; снимки | `testing`, `visual-review` |

Варианты:

- *Таблица `deadlines` с `group_id?`* (как в спеке) — срок урока по потокам разными датами. Отвергнут для MVP: «через N дней от старта
  потока» уже даёт каждому потоку свою дату; отдельная таблица нужна только для ручных дат по потокам — можно добавить позже, не
  ломая колонки урока. Колонки урока — как у расписания открытия (4.3): одно место настройки, без соединений.
- *Жёсткий дедлайн* (после срока сдать нельзя) — отвергнут для MVP: блокирует учеников без выгоды для школы; можно ввести флагом позже.
- *Напоминание по событию в момент срока* (задача на каждый урок каждого ученика) — отвергнут: миллионы отложенных задач; одна ежедневная
  задача со списком «у кого завтра срок» дешевле.

Риски: письма — ПДн (почта): шлются только задачей, в журнал не пишутся; большой курс — выборка «у кого завтра срок» SQL-запросом
по индексу `(school_id, course_id)`, а не перебором в коде. Смена срока урока не порождает повторных писем (отметка уже есть).

Что не трогаем: кабинет ученика со списком сроков (4.5), отчёт по просрочкам для школы и куратора (4.6), письмо куратору о просрочках,
предпочтения и отписка от писем (после MVP), сроки по потокам вручную, жёсткий дедлайн, срок у отдельного блока (теста/задания).

Ядро (`kernel/**`, `packages/ui/**`) **не трогаем**.

| Правило | Что |
| --- | --- |
| Срок урока | нет / через N дней от старта потока ученика (или зачисления) / до даты; до конца дня по Москве; действует сразу, без публикации (`courses.manage`) |
| Просрочка | срок прошёл, урок не завершён; урок **не закрывается**, сдавать можно; после завершения пометка снимается |
| Ученику | в оглавлении и в уроке — «Сдать до …», просроченный — «Срок прошёл …» |
| Напоминания | раз в день в 10:00 по Москве: «завтра срок» и «срок прошёл» — каждое один раз на урок; только действующим зачислениям (не отозванным, не истёкшим) и незавершённым урокам |

### Вопросы владельцу

1. **Срок — в настройках урока** (колонки `lessons.deadline_days`/`deadline_date`, как расписание открытия), без таблицы `deadlines` по потокам —
   подходит? Разные даты потокам даёт «через N дней от старта потока».
2. **Мягкий дедлайн**: после срока урок не закрывается, только пометка и напоминание — подходит?
3. **Срок — до конца дня по Москве** (23:59) — подходит?
4. **Напоминания**: «завтра срок» и «срок прошёл», по одному разу, ежедневно в 10:00 по Москве, только ученику — подходит? (Куратору и
   школе — отчётом в 4.6.)
5. **Письмо о дедлайне делаем в 4.4** (в 4.8 остаётся общий вид писем и сертификат) — подходит?
6. **Имена**: колонки `deadline_days`/`deadline_date`, таблица `deadline_reminders`, задача `learning.deadline-reminders`, письмо
   `learning.deadline-reminder`, тексты «Срок сдачи», «Сдать до …», «Срок прошёл …» — подтвердите.

Утверждено: владелец, 2026-11-10 — «рекомендации одобряю» (все 6 ответов — по рекомендации §3).
