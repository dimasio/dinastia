# 4.7: сертификаты — шаблон курса, PDF, проверка по номеру

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.7 «Сертификаты: шаблон курса, PDF, проверка по номеру»; демо фазы — «полный цикл от приглашения ученика до
сертификата».

Что сейчас:

- Курс пройден → `enrollments.status = completed`, `completed_at`, событие `enrollment.completed` (4.3). Больше ничего не происходит.
- `domain.md` описывает модуль `certificates` (таблицы `certificate_templates`, `certificates`, `certificate_counters`; номер
  `<slug школы>-<год>-<порядковый>`), скилл `documents` — `defineDocument` (React-шаблон → HTML → Chromium → PDF в фоновой задаче,
  D-013). **В коде нет ни модуля, ни `kernel/documents`**; Chromium есть только у e2e (`@playwright/test`, dev-зависимость корня).
- Образец фоновой задачи, которая пишет private-файл, — `kernel/exports` (4.6). Логотипа школы и печатных шрифтов в репозитории нет.

Нужно: школа включает сертификат у курса и настраивает его вид; ученик, прошедший курс, получает PDF с номером; любой (работодатель,
проверяющий) проверяет сертификат по номеру на публичной странице школы.

Варианты:

- *PDF без браузера* (`@react-pdf/renderer`, `pdf-lib`) — легче (нет Chromium в образе воркера), но текст шаблона — rich (Tiptap → HTML),
  его пришлось бы переводить в примитивы PDF; расходится с D-013. Отвергнут; вернёмся, если Chromium окажется дорог в эксплуатации.
- *PDF при скачивании, без хранения* — отвергнут: Chromium в запросе (D-013) и документ меняется вслед за шаблоном; выданный
  сертификат — снимок на момент выдачи.
- *Несколько шаблонов на курс / библиотека шаблонов школы* — после MVP; сейчас один шаблон на курс, один встроенный макет с
  настраиваемыми полями.
- *Номер только порядковый* (`trud-2026-000123`) — перебором номеров публичная проверка отдаёт имена всех учеников школы (ПДн). Поэтому
  проверка по одному номеру показывает имя скрыто, полное — только по ссылке из QR (номер + случайный код) — вопрос 4.

Риски: Chromium в воркере (размер образа, память — один браузер, документы по очереди, таймаут 30 с); номер без дырок и дублей —
счётчик `FOR UPDATE` в той же транзакции, что и запись сертификата; публичная проверка — без утечки ПДн и без перебора (rate limit,
скрытое имя); снимок имени и курса в `certificates` — ПДн, удаляются вместе с участником (`personal-data`).

Что не трогаем: письмо «ваш сертификат готов» (4.8), несколько шаблонов и редактор макета мышью, электронную подпись, логотип школы
(брендинга нет — фоном можно загрузить бланк с логотипом), сертификат за поток/программу из нескольких курсов, отчётность ФИС ФРДО.

**Ядро**: `kernel/documents` и зависимости `playwright-core`, `@fontsource/*`, `qrcode` — **нужно ваше разрешение** (вопрос 1).
**Миграция** `0025_certificates` — только добавление.

| Правило | Что |
| --- | --- |
| Включение | у курса один шаблон; выключен — сертификаты не выдаются, выданные остаются |
| Выдача | при прохождении курса, если шаблон включён; один на зачисление; включили позже — «Выдать прошедшим» |
| Номер | `<SLUG>-<год>-<порядковый с 000001>`, сквозной по школе внутри года, без дублей и пропусков |
| Снимок | имя ученика, название курса, дата и вид шаблона — на момент выдачи; правки шаблона выданное не меняют |
| Аннулирование | сотрудник аннулирует (журнал); проверка показывает «аннулирован», ученик больше не скачивает |
| Проверка | публичная страница школы: номер → статус, курс, дата выдачи, школа, имя (скрыто / полностью — вопрос 4) |
| Ученик | «Скачать сертификат» у пройденного курса; пока PDF готовится — «Сертификат готовится» |

### Вопросы владельцу

1. **Ядро и Chromium**: PDF по D-013 — `kernel/documents` (React-шаблон → Chromium в фоновой задаче), зависимости `playwright-core`
   (Chromium в образе воркера, ~150 МБ), шрифты `@fontsource` (кириллица, OFL), `qrcode` (MIT). **Разрешаете править ядро и добавить их?**
   (Иначе — `@react-pdf/renderer` без браузера, но текст шаблона — без форматирования.)
2. **Вид сертификата**: один встроенный макет с полями — ориентация, заголовок («Сертификат»), текст с подстановками `{имя}`, `{курс}`,
   `{дата}`, подписант (ФИО, должность), картинка подписи, фон (бланк школы с логотипом), показывать номер и дату, QR проверки — подходит?
3. **Выдача**: автоматически при прохождении курса; «Выдать прошедшим» для тех, кто прошёл до включения; аннулирование сотрудником;
   повторно не выдаётся (переоформить = аннулировать и выдать снова) — подходит?
4. **Проверка и ПДн**: страница `/certificates/verify` без входа. Рекомендую: по номеру — статус, курс, дата, школа и имя **скрыто**
   («Иван П.»); по ссылке из QR (номер + случайный код в PDF) — имя полностью. Подходит, или показывать имя полностью по номеру?
5. **Номер**: `TRUD-2026-000123` (slug школы заглавными, год выдачи, сквозной счётчик школы за год) — подходит?
6. **Имена**: модуль `certificates`; право `certificates.manage`; процедуры `certificates.template.get/save`,
   `certificates.list`, `certificates.issueCompleted`, `certificates.revoke`, `certificates.download`, `certificates.verify`; событие
   `certificate.issued`; тексты «Сертификат» (вкладка), «Выдавать сертификат», «Выдать прошедшим», «Аннулировать», «Скачать сертификат»,
   «Проверка сертификата» — подтвердите.

Утверждено: владелец, 2026-11-11 — «рекомендации одобряю» (все 6 ответов — по рекомендации; ядро `kernel/documents`, Chromium,
шрифты, QR — разрешены; имя по номеру — скрыто, полностью — по ссылке из QR).

Отступления при разработке:

- **QR — `uqr` вместо `qrcode`**: у `qrcode` последний релиз — август 2024 (скилл `dependencies`); `uqr` 0.1.3 — MIT, без зависимостей,
  отдаёт SVG. D-059.
- **Предпросмотр — HTML, а не PDF**: та же вёрстка (`documentHtml`) в `iframe sandbox` без скриптов — без задачи и Chromium в запросе
  (D-013), с картинками по подписанным ссылкам. Процедура `certificates.template.preview` (в вопросе 6 её не было).
- **Колонки «Сертификат» на «Учениках» нет** — вместо неё список «Выданные сертификаты» на вкладке «Сертификат» (номер, ученик, дата,
  состояние, «Скачать PDF», «Аннулировать», «Выдать прошедшим»): «Ученики» — ресурс модуля `learning`, сертификаты — `certificates`
  (`certificates → learning`, обратно — цикл).
- **Ссылка QR** — `/certificates/verify?number=…&code=…` (страница проверки с параметрами), а не отдельный `/c/<номер>-<код>`.
- **Право `certificates.own`** (student) — свои сертификаты; в вопросе 6 были только `manage`/`view`.
- **Chromium на macOS** — установленный Google Chrome (`channel: 'chrome'`), как у e2e: Playwright на macOS 13 свой не ставит. В Linux
  (CI, образ воркера) — `playwright install --with-deps chromium`; в CI шаг перенесён до `pnpm check` (тестам API нужен браузер).
- **`storeFile`** в `kernel/storage/files.ts` — общее «сервер записал файл» (выгрузка 4.6 переведена на него), `getObject` в `s3.ts`.
- **Сид `trud`**: шаблон у «Пожарной безопасности»; в сиде нет подписчиков событий — выдача прошедшим явным `issueCompleted` в конце
  (4 сертификата `TRUD-2026-…`, PDF печатает воркер `pnpm dev`); сид теперь закрывает очередь (`stopBoss`), иначе процесс не завершался.
- Кнопка ученика опрашивает список сертификатов первую минуту после прохождения (сертификат выдаёт задача — без опроса кнопка
  появлялась только после перезагрузки страницы; поймал e2e).
