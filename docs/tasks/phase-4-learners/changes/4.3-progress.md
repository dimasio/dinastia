# 4.3: прогресс, открытие уроков по расписанию, настройка доступа к урокам

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.3 «Прогресс: `lesson_progress`, пересчёт по событиям, drip по расписанию, `progress_pct`; экран настройки доступа к
урокам» и открытый вопрос фазы «сброс отклонённой работы».

Что сейчас:

- **Доступность уроков считается при чтении** (D-057, `apps/api/src/modules/learning/access.ts` `computeAccess`): `sequential` — предыдущий
  урок завершён, `drip` — наступили `drip_date` (полночь UTC) или `enrolled_at + drip_days`. Статус урока в БД не хранится;
  `lesson_progress` — только факты `opened_at`/`completed_at`. Спека (`domain.md` §1, §3 «Доступ к урокам») при этом описывает хранимый
  `lesson_progress.status`, `available_at` и пересчёт «по расписанию» — расходится с кодом.
- **`progress_pct`** пересчитывается одной функцией `recalcProgress` (`learning/service.ts:157`), но только когда ученик сам завершает урок.
  Опубликовали новый урок или удалили опубликованный — у остальных учеников процент устаревает до их следующего урока.
  Пройденный курс (`completed`) при этом не «распроходится» (правило MVP в скилле `lms-learners`).
- **Настроек доступа в интерфейсе нет.** `lessons.access_mode`, `drip_days`, `drip_date` и `courses.default_access_mode` есть в БД; режим
  курса меняет только `courses.update` (без экрана), режим урока — только сид и команда `src/enroll.ts`. `courses.lessons.update`
  (`/lessons/{id}/settings`) принимает лишь `completionRule`.
- **Потоки (4.2)**: у потока есть `starts_at`, но расписание его не учитывает — «через N дней» считается от зачисления.
- **Отклонённая работа** (`rejected`) — конечный статус: урок под правилом `all_blocks` с такой работой не завершится никогда (3.6).

Нужно: школа настраивает, как открываются уроки (сразу, по порядку, по расписанию — от старта потока или даты), прогресс учеников
всегда актуален, а отклонённую работу можно разрешить пересдать.

## 2. Архитектура

| Слой | Что меняется | Скилл |
| --- | --- | --- |
| БД | **миграций нет** (поля уже есть). `lesson_progress.status`/`available_at` не вводим — доступность остаётся «при чтении» | `db-schema` |
| Доступ | `computeAccess`: «через N дней» — от `groups.starts_at`, если ученик в потоке со стартом, иначе от `enrolled_at`; `drip_date` — с полуночи **по Москве** (сейчас UTC — ученик в РФ видит урок в 03:00) | `lms-courses`, `lms-learners` |
| Прогресс | задача `learning.recalc-course-progress` `{ courseId }` — пересчитать `progress_pct` всех зачислений курса через `recalcProgress` (идемпотентно, `singletonKey` по курсу); ставится подписчиками на `lesson.published`, `course.published` и при удалении опубликованного урока и смене порога `completion_threshold_pct`. Пройденный курс не «распроходится» | `background-jobs`, `events-automations` |
| Контракт | **добавление**: `courses.lessons.update` — необязательные `accessMode`, `dripDays`, `dripDate` (и `completionRule` становится необязательным); `Lesson` — `dripDays`, `dripDate`; `assessments.assignment.review` — решение `allow_resubmit` | `api-endpoints` |
| Пересдача | решение проверяющего «Разрешить пересдачу» для `rejected`: переход `rejected → needs_revision` (проверяющий, комментарий обязателен), ученик снова сдаёт; событие `submission.reviewed` и письмо — как у «на доработку» | `lms-assessments` |
| Веб | **конструктор курса** — блок «Доступ к урокам»: режим курса (сразу / по порядку / по расписанию); **конструктор урока** — рядом с «Когда урок считается пройденным» переключатель «Когда урок открывается»: как у курса / сразу / после предыдущего / по расписанию — «через N дней после старта» или «с даты»; плеер — «Откроется 12 декабря» уже есть (`lockedBy.date`); экран проверки — кнопка «Разрешить пересдачу» у отклонённой работы | `web-screens`, `screen-design`, `ux-writing` |
| Строки | `courses:access.*`, `assessments:review.allowResubmit.*` | `i18n` |
| Тесты | unit `computeAccess` (поток со стартом, дата по Москве); интеграционные: пересчёт после публикации урока и удаления, порог, пройденный не снимается, настройки урока и права, пересдача (кто может, из какого статуса, урок завершается после принятия); e2e `tests/e2e/access.spec.ts`: преподаватель ставит урок «через 1 день», ученик видит «Откроется …»; пересдача отклонённой работы; снимки | `testing`, `visual-review` |

Варианты:

- *Хранить `lesson_progress.status` и открывать уроки задачей раз в 15 минут* (как в спеке) — отвергнут: дублирует расчёт, который уже
  верен при чтении (D-057), даёт окно рассинхрона и требует пересчёта всех учеников при любой правке курса. Задача по расписанию
  понадобится только для **уведомления** «открылся новый урок» — это письма, пункт 4.8.
- *Пересчитывать процент при чтении* — отвергнут: `progress_pct` нужен в списках и аналитике (4.6) с сортировкой, считать его на лету
  для сотен учеников дорого.

Риски: смена режима доступа опубликованного курса сразу меняет доступность у всех учеников (может закрыть уже открытые уроки) — в
интерфейсе предупреждение; уроки, которые ученик уже завершил, остаются открытыми (так считает `computeAccess`). Пересчёт процента
большого курса — фоновой задачей, не в запросе.

Что не трогаем: дедлайны (4.4), письмо «открылся урок» (4.8), кабинет ученика (4.5), аналитика (4.6), часовой пояс школы как настройка
(пока — Москва для всех), «распрохождение» курса.

Ядро (`kernel/**`, `packages/ui/**`) **не трогаем**.

### Вопросы владельцу

1. **Доступность при чтении** (без хранимого статуса урока и без задачи «открыть уроки»), спеку привести к коду — подходит?
2. **«Через N дней» — от старта потока**, если ученик в потоке со стартом, иначе от зачисления — подходит?
3. **«С даты» — с полуночи по Москве** для всех школ (настройка часового пояса — позже) — подходит?
4. **Пересчёт процента** задачей при публикации, удалении урока и смене порога; пройденный курс остаётся пройденным, даже если процент
   упал — подходит?
5. **Где настраивать**: режим курса — в конструкторе курса, режим урока — в конструкторе урока рядом с правилом завершения — подходит?
6. **«Разрешить пересдачу»** входит в 4.3 (`rejected → needs_revision`, комментарий обязателен) — подходит?
7. **Имена**: задача `learning.recalc-course-progress`, решение `allow_resubmit`, тексты «Когда урок открывается», «Разрешить пересдачу» —
   подтвердите.

Утверждено: владелец, 2026-11-10 — «рекомендации одобряю» (все 7 ответов — по рекомендации §3).
