# 4.6: аналитика курса — ученики и прогресс, воронка по урокам, результаты тестов, экспорт xlsx

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.6 «Аналитика школы: ученики курса и их прогресс, воронка по урокам, результаты тестов; экспорт xlsx».

Что сейчас:

- Вкладка курса «Ученики» (4.1–4.2): имя, почта, поток, статус, зачислен, доступ до, `progress_pct`; фильтры по статусу и потоку,
  куратор видит только свои потоки (`groupScope`). Сколько уроков пройдено, когда ученик был последний раз, что просрочено — не видно.
- Данные для аналитики есть: `lesson_progress` (`opened_at`, `completed_at`), сроки — `computeAccess` → `overdue` (4.4),
  `quiz_attempts` (`score`, `max_score`, `passed`, `status`), `submissions` (статусы).
- Экспорта нет. Скилл `documents` описывает `defineExport` (фоновая задача → xlsx/csv в private-файл), но **в ядре его нет**
  (`kernel/**` — без `documents`/`export`), зависимости для xlsx в репозитории нет.
- Модули: `assessments → learning` (обратно — цикл, см. 4.5).

Нужно: школа (владелец, администратор, преподаватель, куратор — в своих потоках) видит по курсу, кто как учится, где ученики
«отваливаются», как сданы тесты, и выгружает учеников с прогрессом в Excel.

| Слой | Что меняется | Скилл |

Зависимость `exceljs` (потоковая запись). Первый экспорт — `learning.course-students`: колонки «Учеников» + пройдено уроков, просрочено, последняя активность; учитывает фильтры (поток, статус). Запись в журнал `exports.created` (в файле ПДн — почта и имя) | `documents`, `background-jobs`, `files-media`, `dependencies`, `personal-data`, `core-kernel` |
| Веб | вкладка курса **«Аналитика»** (`/admin/courses/$courseId/analytics`): фильтр по потоку; карточки сводки; воронка — список уроков с полосами «открыли / прошли» и числом просрочек (CSS-полосы, без библиотеки графиков); таблица тестов и заданий. На «Учениках» — новые колонки и действие «Выгрузить в Excel» (ждёт задачу, затем скачивание). Экспорт из ядра — действие ресурса `export` в `packages/ui/resource` (**ядро**) | `web-screens`, `admin-resource`, `screen-design`, `ux-writing` |
| Строки | `learning:analytics.*`, `learning:export.*`, `assessments:results.*`, `common:export.*`, `errors:*` | `i18n` |
| Тесты | интеграционные: сводка и воронка (числа, %, просрочки, поток, изоляция школ, куратор — только свои потоки, ученик — нет права), результаты тестов (лучшая попытка, ручная проверка), новые колонки «Учеников»; ядро — `defineExport` (задача, файл, права, срок ссылки, чужая школа), xlsx читается обратно и содержит строки; e2e `analytics.spec.ts`: преподаватель открывает «Аналитику», видит воронку, выгружает xlsx; снимки | `testing`, `visual-review` |

Варианты:

- *Отдельный модуль `analytics`* (читает таблицы `learning` и `assessments`) — отвергнут: модуль читает только свои таблицы; агрегаты
  считают владельцы данных, экран собирает два запроса.
- *Экспорт в браузере* (xlsx собирается на клиенте из страниц API) — проще, без ядра, но вся выборка в памяти браузера, большая
  библиотека в бандле и расходится со скиллом `documents` (D-013: тяжёлое — в фоновой задаче). Отвергнут, если разрешите ядро.
- *Синхронный экспорт в запросе* — отвергнут: большой курс держит запрос и соединение БД.
- *Таблица-кэш агрегатов* (пересчёт по событиям) — не нужен для MVP: запросы по индексам на курсе до тысяч учеников укладываются в
  бюджет; вернёмся, если `performance` покажет.
- *Аналитика по всей школе* (сводка по курсам на главной кабинета школы) — после MVP.

Риски: агрегаты по большому курсу — считать SQL (`count … group by lesson_id`), не перебором учеников в коде; воронку с просрочками
(просрочка считается в коде из сроков) — одним проходом по фактам курса. Экспорт содержит ПДн: только по праву, private-файл, ссылка
короткая, файл удаляется через 24 ч, событие в журнале. Куратор не должен получить учеников чужих потоков ни в аналитике, ни в
выгрузке (тот же `groupScope`).

Что не трогаем: аналитику по всей школе, графики во времени (активность по дням), выгрузку ответов на тесты по вопросам, отчёты
для руководителя по почте, сертификаты (4.7).

**Ядро**: `kernel/exports` (`defineExport`, задача, назначение файла, процедуры) и действие `export` в `packages/ui/resource` —
**нужно ваше разрешение** (вопрос 1).

### Вопросы владельцу

1. **Ядро**: делаем экспорт по скиллу `documents` — `defineExport` в ядре (фоновая задача → xlsx-файл, ссылка на 24 ч) и действие
   «Выгрузить» в ресурс-фреймворке `packages/ui`; зависимость `exceljs`. **Разрешаете править ядро и добавить `exceljs`?**
   (Иначе — выгрузка собирается в браузере, без ядра.)
2. **Где аналитика**: новая вкладка курса «Аналитика» (сводка, воронка, тесты), а прогресс по ученикам — новыми колонками на
   существующих «Учениках» (там же выгрузка) — подходит?
3. **Кто видит**: новое право `learning.analytics` — администратор, преподаватель, куратор (только свои потоки) — подходит?
4. **Тесты**: «сдал» — по лучшей попытке; средний балл — по лучшим попыткам — подходит?
5. **В Excel** — один лист «Ученики» (имя, почта, поток, статус, зачислен, доступ до, прогресс %, пройдено уроков, просрочено,
   последняя активность) с фильтрами экрана — подходит? (Воронку и тесты в файл — позже.)
6. **Имена**: право `learning.analytics`, процедуры `learning.analytics.course`, `assessments.results.course`, `exports.start`/`exports.get`,
   экспорт `learning.course-students`; тексты «Аналитика», «Открыли», «Прошли», «С просрочкой», «Последняя активность»,
   «Выгрузить в Excel» — подтвердите.

Утверждено: владелец, 2026-11-10 — «рекомендации одобряю» (все 6 ответов — по рекомендации §3; ядро править и добавить библиотеку xlsx
разрешено).

Отступления при разработке:

- **`write-excel-file` вместо `exceljs`**: у `exceljs` последний релиз — декабрь 2024 (скилл `dependencies`: релиз за 12 месяцев);
  `write-excel-file` 4.1.1 — MIT, одна зависимость, свои типы, релиз 2026. Собирает файл в памяти (на 100 тыс. строк хватает). D-058.
- **Миграция `0024_exports`** (только добавление): таблица ядра `exports` — состояние выгрузки и параметры, проверенные в запросе
  (аналитика по-прежнему без миграции).
- Действие выгрузки в ресурс-фреймворке — общее `pageActions` (кнопка над списком с текущими фильтрами), а не специальное `export`:
  `packages/ui` не знает про API, запуск и ожидание файла — `apps/web/src/app/exports.ts`.
- **Найдена и исправлена ошибка 4.1**: маршруты «Учеников» и банка вопросов удаляли кэш списка в `beforeLoad`; предзагрузка по
  наведению удаляла запрос, который экран уже ждёт, — список изредка навсегда оставался заглушкой (плавающий e2e `groups`). Теперь
  у ресурса есть `scope` (область кэша = курс), удаление убрано; `groups` — 8 из 8.
- В тестах воркер при старте удалял ждущие задачи **соседних** тестовых файлов (с 4.3) — теперь только задачи удалённых школ
  (`src/test/jobs.ts`); плавал `progress.test`.
- Чтобы избежать цикла файлов `service.ts` ↔ `enrollment.service.ts`, расчёт состояния курса вынесен в `learning/state.ts`
  (`courseStates` — оглавление одно на курс).
