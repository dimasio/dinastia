# 4.8: транзакционные письма — приглашение, зачисление, ДЗ проверено, дедлайн, сертификат

Задача: [phase-4-learners](../task.md) · Шаг: готово

## 1. Запрос

Источник — роадмап 4.8 «Транзакционные письма: приглашение, зачисление, ДЗ проверено, дедлайн, сертификат»; план фазы: «письма, нужные
раньше, делаются в своём пункте; 4.8 — оставшиеся и общий вид».

Что сейчас (сверка с кодом):

| Письмо | Есть | Где |
| --- | --- | --- |
| приглашение сотрудника в школу | да | `schools.invitation` (1.x), токен — задача |
| приглашение на курс (незнакомая почта) | да | `learning.course-invitation` (4.1(б)), токен — задача |
| «вас записали на курс» | да, только при зачислении сотрудником | `learning.enrolled` (4.1) |
| ДЗ проверено (принято / доработка / отклонено) | да | `assessments.submission-reviewed` (3.5) |
| «завтра срок» / «срок прошёл» | да | `learning.deadline-reminder` (4.4), 10:00 МСК |
| **сертификат готов** | **нет** | событие `certificate.issued` есть (4.7), подписчика нет |
| **тест проверен вручную** | **нет** | `domain.md`: «письма о результате ручной проверки теста нет»; событие `quiz.graded` есть |
| **открылся урок по расписанию** | **нет** | обещано в 4.3 (`domain.md` §3 «Доступ к урокам», скилл `lms-learners`) |
| **вход по ссылке** (magic link) | есть, но **вне шаблонов** | `kernel/auth/auth.ts`: текст литералом, без i18n и вида школы, тема «Вход в Dinastia» |

Общий вид: макет `EmailLayout` (название школы, подвал) есть, но кнопка в каждом письме — своя копия инлайн-стилей (5 мест), письмо
входа — голый текст. Сотрудникам писем о новых работах на проверку нет (очередь — экран «Проверка»).

Нужно: ученик узнаёт по почте обо всём, что от него ждут или что для него готово; все письма — в одном виде школы.

| Строки | `emails:*` (новые письма, вход), без литералов в `auth.ts` | `i18n`, `ux-writing` |

Варианты:

- *PDF сертификата во вложении* — отвергнут: файл с ПДн уходит в почтовые ящики навсегда, письмо тяжелеет; ссылка ведёт в кабинет.
- *«Открылся урок» сразу в момент открытия* (задача на каждый урок каждого ученика) — отвергнут: тысячи отложенных задач; раз в день
  одной задачей проще и письма собираются в одно.
- *Письма сотрудникам* («новая работа на проверку», «ученик прошёл курс») — после MVP вместе с настройками уведомлений и отпиской
  (иначе куратор с сотней учеников получает сотни писем); сейчас очередь — экран «Проверка». Вопрос 4.
- *Настройки писем в школе и отписка* — после MVP (скилл `notifications`: с первыми не транзакционными письмами); все письма 4.8 —
  транзакционные.

Риски: письмо входа — ядро аутентификации: шаблон рендерится синхронно в обработчике better-auth, токен в очередь не попадает (как
сейчас); ошибки рендера не должны ломать вход — проверяется тестом. «Открылся урок» — расчёт доступа на всех зачислениях школы:
одна выборка на курс (`courseStates`), только курсы с уроками `drip`. Дубли писем — уникальная отметка в той же транзакции, что и
постановка письма.

Что не трогаем: письма сотрудникам, настройки уведомлений и отписку, Telegram/push (R3), письмо «курс пройден» без сертификата
(вопрос 3), тексты существующих писем.

**Ядро**: `kernel/mail` (`EmailButton`, `EmailNote`) и письмо входа в `kernel/auth` — **нужно ваше разрешение** (вопрос 1).
**Миграция** `0026` — только добавление таблицы отметок.

### Вопросы владельцу

1. **Ядро**: общая кнопка и мелкий текст в `kernel/mail`, письмо входа по ссылке — шаблоном с названием школы (сейчас голый текст
   «Вход в Dinastia»). **Разрешаете править ядро** (`kernel/mail`, `kernel/auth`)?
2. **«Открылся урок»**: раз в день в 09:00 по Москве, одно письмо на курс со списком открывшихся уроков; только уроки **по расписанию**
   (открытые сразу и «после предыдущего» — без письма). Новая таблица отметок `lesson_open_notices` (миграция) — подходит?
3. **Сертификат и прохождение**: письмо «сертификат готов» со ссылкой в кабинет (PDF не вкладываем). Курс без сертификата — **письма
   «курс пройден» нет** (рекомендую: ученик видит это на экране; добавить можно вместе с настройками писем) — подходит?
4. **Сотрудникам** писем не шлём (новые работы — на экране «Проверка»); письма кураторам — после MVP вместе с настройками и отпиской —
   подходит?
5. **Тест**: письмо только после **ручной** проверки (автопроверку ученик видит сразу) — подходит?
6. **Имена**: письма `certificates.issued`, `assessments.quiz-graded`, `learning.lessons-opened`, `auth.magic-link`; задача
   `learning.lesson-opened-notices`; таблица `lesson_open_notices`; темы — «Школа: сертификат по курсу «…» готов», «Школа: тест «…»
   проверен», «Школа: открылись новые уроки курса «…»», «Вход в «Школа»» — подтвердите.

Утверждено: владелец, 2026-11-11 — «рекомендации одобряю» (все 6 ответов — по рекомендации; ядро `kernel/mail`, `kernel/auth` править
разрешено).

Отступления при разработке:

- Кроме `EmailButton` и `EmailNote` — `EmailQuote` (комментарий проверяющего в письме «работа проверена»; был инлайн-стилем).
- Письмо входа с корня — отправитель «Dinastia» и свой подвал (`emails:layout.footerPlatform`): «письмо от школы» там неверно.
- `computeAccess` отдаёт `opensAt` (момент открытия по расписанию) — по нему задача решает, что открылось; доступ по-прежнему
  считается при чтении.
- Баллы в письме теста — с запятой («9,5 из 12»).
- **Найдена и исправлена ошибка (с 0.x)**: пользователь, созданный входом по ссылке (присоединение по приглашению), получал **пустое
  имя** — пустая строка в «Учениках», очереди проверки, сертификате и проверке номера. Теперь `databaseHooks.user.create` в
  `kernel/auth/auth.ts` подставляет часть почты до «@» (как при создании аккаунта администратором). Нашёл демо фазы 4. Данные не
  правились: в локальной базе такие пользователи — только из e2e.
- Тесты API: клиент `src/test/http.ts` начинал счётчик адресов с нуля в каждом файле — файлы одного воркера повторяли адреса и
  упирались в лимит регистраций (5 в минуту); теперь — со случайного места.
- Лимит запросов ссылки для входа (3 в минуту с IP) вне production поднимается тем же `AUTH_SIGN_IN_LIMIT` (D-044): в полном e2e
  несколько сценариев входят по ссылке с 127.0.0.1, демо фазы упиралось в 429.
- **Демо фазы 4** — `tests/e2e/phase-4.spec.ts`: приглашение незнакомой почты в поток → вход по ссылке → кабинет (продолжить, срок) →
  задание → куратор потока принимает → письмо «сертификат готов» → PDF → аналитика → проверка номера.
