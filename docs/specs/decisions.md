# Журнал решений

Решение — строка `D-NNN`: что решили и почему. Отменённое не удаляется: пометка «устарело, D-NNN».

| № | Решение | Почему |
|---|---|---|
| D-001 | **Не строим платформу метаданных**; продукт — модульный монолит с типизированными реестрами | предметная область LMS стабильна; ценность — в продуктовом UX (плеер, конструктор, проверка ДЗ), а не в универсальных формах; рантайм метаданных удвоил бы объём (движок + продукт). Low-code для школ — данные в БД (блоки, тесты), для разработчиков — реестры и генераторы |
| D-002 | TypeScript strict, Node 24 LTS, ESM | один язык для сервера, клиента, контрактов и блоков; агенты лучше всего работают с типизированным кодом |
| D-003 | pnpm + Turborepo, Biome | быстрые установки и кэш задач; Biome — один инструмент для линта и формата |
| D-004 | Hono + oRPC + zod, contract-first | типобезопасный клиент без кодогенерации, OpenAPI для мобильного приложения и интеграций из того же контракта; zod-схемы переиспользуются формами. Запасной вариант — tRPC v11 + trpc-to-openapi |
| D-005 | PostgreSQL 17+, Drizzle ORM | SQL-подобный типизированный построитель, схема в TS, миграции drizzle-kit, поддержка RLS-политик в схеме |
| D-006 | Мультитенантность: общая БД + `school_id` + RLS | одна схема — простые миграции; RLS — вторая линия защиты, если код забыл фильтр. Отдельная БД на школу — только для крупных клиентов позже |
| D-007 | better-auth (email+пароль, magic link, organization) | готовые сессии, magic link, организации и приглашения; данные в нашей БД (152-ФЗ) |
| D-008 | pg-boss вместо Redis-очередей | одна зависимость (Postgres), постановка задачи в той же транзакции, что и данные; Redis — когда понадобится (кэш, realtime) |
| D-009 | React 19 + Vite SPA, TanStack Router/Query/Table, shadcn/ui + Tailwind 4 | кабинеты не требуют SEO; файловые типизированные маршруты; shadcn — код компонентов у нас, легко брендировать. SEO-сайт школы — отдельное `apps/site` (SSR) после MVP |
| D-010 | Tiptap для текста, dnd-kit для перетаскивания | JSON-документ вместо HTML — безопасно и мигрируемо; конструктор уроков = список блоков с dnd |
| D-011 | S3-совместимое хранилище, видео через интерфейс провайдера (Kinescope по умолчанию) | данные в РФ; защита видео и адаптивный стрим без своего транскодинга на старте |
| D-012 | Почта через интерфейс провайдера; шаблоны писем — React Email | смена провайдера без правок модулей; письма тестируются как компоненты |
| D-013 | PDF из HTML-шаблона через Chromium в фоновой задаче | сертификаты верстаются тем же стеком; тяжёлая работа вне запроса |
| D-014 | i18n с первого дня, по умолчанию `ru` | рынок РФ сейчас, выход за рубеж без переписывания |
| D-015 | Интеграционные тесты на реальном Postgres (не моки) | RLS и SQL проверяются только на настоящей БД |
| D-016 | Хостинг, логи, ошибки — в РФ (152-ФЗ) | персональные данные учеников; GlitchTip вместо облачного Sentry |
| D-017 | Из GaskarFM переносим процессы и идеи, не код и формат | `docs/specs/legacy-mapping.md` |
| D-018 | Структура курса: курс → раздел → урок → блоки; «раздел», а не «модуль» | «модуль» занят под модуль кода |
| D-019 | Черновик и публикация урока — две JSONB-колонки (`draft_blocks`, `published_blocks`) | ученики видят только опубликованное; полноценная история версий — позже, если понадобится |
| D-020 | Правильные ответы никогда не отдаются ученику; проверка — только на сервере | `toPublic()` у блоков и вопросов, тест в `check:registries` |
| D-021 | Журнал действий сотрудников в ядре (`ctx.audit`, таблица `audit_log`, только добавление) | школам нужно знать, кто поменял оценку, роль, удалил урок; база для разборов инцидентов |
| D-022 | ПДн помечаются в схеме (`pii()`), согласия хранятся в `consents`, удаление ученика — обезличивание | 152-ФЗ: маскирование логов, экспорт и удаление по запросу без ручного поиска полей; статистика школы сохраняется |
| D-023 | Внешние сервисы — только за интерфейсом провайдера с обязательным фейком; исходящие запросы — через `ctx.http`; вебхуки — с подписью и идемпотентностью (`webhook_events`) | работа без сети локально и в CI, защита от SSRF и дублей, смена провайдера без правок модулей |
| D-024 | Git: ветки `<тип>/<slug>`, Conventional Commits на русском, squash-merge; агент коммитит только по просьбе | читаемая история и changelog; контроль человека |
| D-025 | Единый глоссарий терминов (`docs/specs/glossary.md`) для UI, кода и документов | без синонимов «модуль/раздел», «группа/поток» в интерфейсе и разговорах с агентами |
| D-026 | Консоль оператора SaaS (`/ops`) входит в MVP (фаза 5); операторы — глобальная роль `users.platform_role = operator`, не роль школы; вход от имени — только с записью в `audit_log` и видимым баннером | поддержка школ и модерация без доступа к БД; прозрачность для школы |
| D-027 | Скиллы подключаются только к Claude Code (`.claude/skills`); Cline не поддерживаем | один агентский стек, меньше поддержки ссылок |
| D-028 | Термины и названия ролей фиксированы, школа их не переименовывает | проще i18n, единый язык поддержки и документации; пересмотр — только новым решением |
