# Правила документации и изменений

Проверка — `pnpm docs:check` (шапки, ссылки, все скиллы есть в `AGENTS.md` и наоборот).

## Куда класть

| Что                                                                            | Куда                                 |
| ------------------------------------------------------------------------------ | ------------------------------------ |
| как устроено и зачем — для человека                                            | `guide/`                             |
| точный формат, контракт, модель данных                                         | `specs/`                             |
| пошаговая инструкция для агента                                                | `skills/`                            |
| то, что живёт, пока идёт работа: постановка, план, заметки, карточки изменений | `tasks/`                             |
| решение с причиной                                                             | `specs/decisions.md`, строка `D-NNN` |

Одно знание — в одном месте: скилл ссылается на спеку, а не пересказывает её. Закрывая задачу, долговечное переносится
из `tasks/` в `specs/`, `skills/`, `guide/`.

## Шапки

Задача `tasks/<slug>/task.md`:

```yaml
---
status: active # backlog | active | review | done | dropped
area: core # core | product
phase: 0 # фаза роадмапа, если есть
created: 2026-10-24
closed: # для done и dropped
---
```

Спека: `status: draft | current | outdated`.

## Изменения продукта

Любое изменение поведения продукта — по скиллу `change-workflow` (шесть шагов, карточка изменения
`tasks/<задача>/changes/<slug>.md`, утверждение человеком до разработки, поэтапная проверка через `git add`).

## Оформление

- Русский язык; идентификаторы, код, пути — как в исходниках.
- Ссылки на код — `путь:строка` от корня репозитория.
- Файлы и папки — латиницей через дефис.
