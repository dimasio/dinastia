# Развёртывание и масштабирование

Всё, что касается запуска Dinastia вне машины разработчика: состав, характеристики серверов, конфигурация, порядок
выката, масштабирование, бэкапы. Процесс релиза и правила миграций — скилл `release-deploy`; логи, метрики и
оповещения — скилл `observability`. Документ дополняется в пунктах 5.3 (стенд в РФ) и фазе 6 «Упаковка».

> Цифры ниже — оценка по текущему коду (пулы подключений, процессы, Chromium для PDF), не по нагрузочному тесту.
> После пилота (5.7) — уточнить по метрикам и записать сюда фактические значения.

## Состав

| Компонент | Что делает | Зависимости |
| --- | --- | --- |
| `api` | HTTP: oRPC `/api/*`, вход (better-auth), вебхуки, `/health/*` | Postgres, S3, SMTP |
| `worker` | pg-boss: фоновые задачи, подписчики событий, расписания, печать PDF (Chromium) | Postgres, S3, SMTP |
| `web` | статические файлы сайта (Vite-сборка) за nginx/Caddy/CDN | — |
| `migrate` | одноразовый шаг: миграции до выката нового кода | Postgres (владелец) |
| PostgreSQL 18 | данные школ (RLS), очередь pg-boss, лимиты частоты | — |
| S3 | файлы школ, PDF сертификатов, выгрузки | — |
| SMTP | письма (вход по ссылке, приглашения, уведомления) | — |
| GlitchTip | сбор ошибок (Sentry SDK), D-061 | свой Postgres + Valkey/Redis |
| Prometheus + Alertmanager | метрики с `METRICS_PORT`, правила `docker/monitoring/alerts.yml`, оповещения в Telegram | — |

`api` и `worker` — один образ, разные команды. Состояния в процессах нет (сессии и очередь — в Postgres), поэтому оба
масштабируются копиями.

Расход подключений к Postgres на один процесс: пул приложения — 10, pg-boss — 5 (воркер) и 2 (отправка задач из API).
Итого примерно **17 на пару `api`+`worker`**. Это ограничивает число копий (см. «Масштабирование»).

## Характеристики

### Минимум — бюджетный тестовый стенд

Один виртуальный сервер, всё в `docker compose`: Postgres, SeaweedFS вместо облачного S3, `api`+`worker`, Caddy (TLS
Let's Encrypt), GlitchTip и Prometheus — по желанию.

| Ресурс | Без мониторинга | С GlitchTip и Prometheus |
| --- | --- | --- |
| vCPU | 2 (можно с долей 50 %) | 2 (100 %) |
| RAM | 4 ГБ | 6–8 ГБ |
| Диск | 40 ГБ SSD | 60 ГБ SSD |
| Сеть | публичный IPv4, домен с wildcard DNS `*.<домен>` | то же |

Распределение памяти (ориентир): Postgres 1 ГБ, `api` 300–400 МБ, `worker` 300 МБ + Chromium 300–500 МБ при печати PDF,
SeaweedFS 200 МБ, Caddy 50 МБ, ОС 500 МБ. GlitchTip (web, worker, свой Postgres, Valkey) — ещё 1,5–2 ГБ, Prometheus —
300–500 МБ.

Ограничения минимума: нет отказоустойчивости, бэкап — только `pg_dump` по расписанию на внешнее хранилище, реальные
персональные данные **не загружать** (сервер не аттестован, ПДн — только на prod, пункт 5.5). Для стенда в РФ
подходит самый простой ВМ у Yandex Cloud или Selectel; стоимость — по калькулятору провайдера.

Письма на стенде: Mailpit (письма не уходят наружу, смотреть в веб-интерфейсе) или тестовый ящик SMTP-провайдера.

### Рекомендуемо — пилот и первые школы (до ~20 школ, ~2 000 учеников, ~200 одновременно)

| Компонент | Характеристики |
| --- | --- |
| `api` | 2 копии × 1 vCPU / 1 ГБ (две — чтобы выкат шёл без простоя) |
| `worker` | 1 копия × 1 vCPU / 2 ГБ (Chromium) |
| `web` | статика в Object Storage + CDN или nginx на той же ВМ |
| PostgreSQL | Managed, 2 vCPU / 8 ГБ, 50 ГБ SSD, PITR 7 дней, снапшоты 30 дней |
| S3 | Managed Object Storage, версионирование, lifecycle для `exports/` |
| SMTP | транзакционный провайдер в РФ, SPF/DKIM/DMARC для домена отправителя |
| Мониторинг | отдельная ВМ 2 vCPU / 4 ГБ / 40 ГБ: GlitchTip, Prometheus, Alertmanager |

Контейнеры `api`/`worker` — либо ВМ 4 vCPU / 8 ГБ с compose, либо Managed Kubernetes (если планируется рост).

### Максимум — что упрётся первым и как расти

Жёсткого максимума нет: процессы без состояния, рост — копиями `api`/`worker` и размером Postgres. Узкие места по
порядку появления:

1. **Подключения к Postgres.** ~17 на пару процессов; при 10+ копиях — PgBouncer (transaction mode) перед Postgres или
   уменьшить пул. RLS ставит контекст школы через `set_config(..., true)` внутри транзакции — совместимо с transaction mode.
2. **Печать PDF.** Один Chromium на воркер; массовая выдача сертификатов — отдельные воркеры только под очередь
   `certificates.*` (по метрике `job_duration_seconds` и отставанию очереди).
3. **CPU и память Postgres.** Ориентир — 4–8 vCPU / 16–32 ГБ на 200+ школ; дальше — реплика для чтения (отчёты, выгрузки).
4. **pg-boss.** Очередь в той же БД; при сотнях тысяч задач в сутки — отдельная БД под очередь.
5. **Видео** не через нас: Kinescope отдаёт поток сам, S3 — только файлы и PDF.

## Конфигурация

Все переменные — `.env.example` (проверка — `apps/api/src/kernel/config.ts`, при ошибке процесс не стартует). Для
стенда и prod обязательно:

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` (включает жёсткие лимиты входа) |
| `APP_DOMAIN`, `APP_PROTOCOL` | основной домен, `https` |
| `AUTH_SECRET` | случайная строка ≥ 32 символов, своя на каждое окружение |
| `DATABASE_URL` / `DATABASE_URL_OWNER` | роль приложения (под RLS) / роль владельца (только `migrate`) |
| `TRUST_PROXY_HOPS` | число прокси перед API: 1 — Caddy/ingress, 2 — CDN + ingress (D-042) |
| `S3_*` | бакет и ключ с правами только на этот бакет |
| `SMTP_*`, `SMTP_FROM` | провайдер писем |
| `SENTRY_DSN`, `SENTRY_DSN_WEB` | проекты GlitchTip для сервера и сайта (второй — при сборке `web`); пусто — сбор выключен |
| `APP_RELEASE` | тег или SHA сборки |
| `METRICS_PORT` | внутренний порт метрик, наружу не публикуется |

## Сеть, домены, безопасность

- Wildcard DNS и TLS: `<slug>.<домен>` и `<домен>`. Wildcard-сертификат Let's Encrypt — через DNS-проверку (API DNS
  провайдера).
- Домен файлов — **вне** `*.<домен>` (например, отдельный домен бакета); CORS бакета — только сайты школ.
- Веб-сервер отдаёт CSP из `apps/web/csp.ts` (`dev: false`), HSTS, `nosniff` (аудит 5.1).
- Наружу открыты только 80/443. Postgres, `METRICS_PORT`, Prometheus, панель SeaweedFS — только во внутренней сети или
  по VPN/SSH.
- Хостинг и данные — в РФ (152-ФЗ, скилл `personal-data`).

## Порядок выката

`migrate` → `worker` → `api` → `web`, затем smoke-тест: `/health/ready` (БД и хранилище), вход, открыть урок.
Подробно, вместе с откатом и правилами миграций, — скилл `release-deploy`. Автоматизация (CI/CD, установщик,
обновления) — фаза 6.
