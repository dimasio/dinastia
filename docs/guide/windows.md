# Dinastia на Windows: установка с флешки и лаунчер

Пакет для показа и проверки платформы на отдельном компьютере с Windows (D-069): один инсталлятор ставит всё, что нужно,
без Docker, WSL, прав администратора и интернета; лаунчер `Dinastia.exe` запускает платформу и открывает учебный центр в
отдельном окне. Это **демо-стенд на одном компьютере**: адреса `*.education.localhost` открываются только на нём; показать
платформу на телефоне или другом компьютере в той же сети Wi‑Fi — сетевой режим (ниже). Сервер для слушателей — не этот пакет. Сервер — [deployment.md](deployment.md); вручную из исходников через Docker — [windows-manual.md](windows-manual.md).

## Что внутри

| Часть | Что | Где после установки |
| --- | --- | --- |
| `DinastiaSetup-<версия>.exe` | инсталлятор (Inno Setup), около 400–500 МБ | — |
| `Dinastia.exe` | лаунчер (Python, окно — WebView2, встроен в Windows 10/11) | `C:\Dinastia\` |
| PostgreSQL 18, SeaweedFS (S3), Mailpit (почта), Node 24, Chromium (PDF) | среды выполнения — те же версии, что в `docker/compose.yml` | `C:\Dinastia\runtime\` |
| API, воркер задач, миграции, сид, веб, шлюз | сборка поставки (5.8, D-066) + сид АИР «Горизонт» | `C:\Dinastia\app\` |
| база, файлы, письма, логи, `config.json` (порты, пароли) | создаётся при установке | `C:\Dinastia\data\` |

Пароли базы, ключ сессий и ключи хранилища — случайные, свои на каждой установке (`data\config.json`). Все службы
слушают только `127.0.0.1`: из сети компьютер не виден, брандмауэр не спрашивает разрешений (кроме сетевого режима).

## Установка

Требования: Windows 10 (1809+) или 11, x64; 2 ГБ свободного места; 4 ГБ памяти.

1. Скопировать `DinastiaSetup-<версия>.exe` на флешку и на целевой компьютер.
2. Запустить. Windows может показать «Система Windows защитила ваш компьютер» (инсталлятор не подписан): **Подробнее →
   Выполнить в любом случае**.
3. Путь — `C:\Dinastia` (можно другой, но только латиницей и без пробелов: PostgreSQL на Windows не работает с кириллицей
   в путях). В конце установка 1–3 минуты готовит базу, хранилище и демо-данные.
4. «Запустить Dinastia» — или ярлык «Dinastia» на рабочем столе / в «Пуске».

Данные учебного центра — те же, что `pnpm db:seed` (скилл `local-env`): учебный центр АИР «Горизонт», курс «Оказание
первой помощи…», пароль у всех `gorizont2026`. Список — меню **Dinastia → Пользователи демо-данных** (или
`C:\Dinastia\data\accounts.txt`):

| Роль | Почта |
| --- | --- |
| владелец | `kornev@airgorizont.local` |
| администратор | `tikhomirov@airgorizont.local` |
| куратор | `ivanov@airgorizont.local` |
| слушатель | `tikhomirova@airgorizont.local` |
| оператор `/ops` | `ops@airgorizont.local` (второй фактор настраивается при первом входе) |

## Лаунчер

`Dinastia.exe` запускает PostgreSQL → хранилище → почту → API и воркер → шлюз (показывает шаги), затем открывает
`http://airgorizont.education.localhost` (если порт 80 занят — `:8080` или следующий свободный; выбирается при установке).
**Закрытие окна останавливает все службы.** Повторный запуск при открытом окне — подсказка, что Dinastia уже запущена.

Меню **Dinastia**:

| Пункт | Что |
| --- | --- |
| Учебный центр | кабинет АИР «Горизонт» |
| Консоль оператора | `/ops` на корневом адресе |
| Доступ из сети Wi‑Fi: включить / выключить… | сетевой режим (ниже) |
| Адрес для других устройств | адрес и QR-код для телефона в сетевом режиме |
| Почта (письма платформы) | Mailpit — все письма (приглашения, ссылки для входа, проверка заданий) попадают сюда, наружу не уходят |
| Пользователи демо-данных | логины выше |
| Сбросить демо-данные… | база, файлы и письма — заново, учебный центр загружается снова (после подтверждения) |
| Папка логов | `C:\Dinastia\data\logs`: `launcher.log`, `api.log`, `worker.log`, `postgres.log`, `s3.log`, `mail.log`, `gateway.log` |

Режим работы — демо, как локальная разработка (`NODE_ENV=development`): видео — заглушка провайдера, письма — в Mailpit.

## Доступ из сети Wi‑Fi

Показать платформу на телефонах и других компьютерах в той же сети Wi‑Fi: **Dinastia → Доступ из сети Wi‑Fi: включить /
выключить…** → подтвердить → Windows спросит права администратора (один раз). Затем окно **Адрес для других устройств**
показывает адрес и QR-код: `http://airgorizont.<IP через дефис>.sslip.io` (например, `airgorizont.192-168-1-50.sslip.io`;
с портом, если 80 был занят). Войти на этом компьютере придётся заново — адрес другой.

Как устроено: адрес `*.sslip.io` — публичный DNS, который отвечает IP из самого имени, поэтому корень и учебный центр
работают на любом устройстве без настроек. Шлюз слушает все интерфейсы и отдаёт файлы хранилища на своём порту; API,
база, SeaweedFS и почта Mailpit остаются только на этом компьютере. Брандмауэр получает правило «Dinastia»: входящие к
`node.exe` этой установки на порты веба и хранилища, **только для частных сетей**; если текущая сеть «Общедоступная»,
она переключается в «Частную» (с тем же подтверждением). IP проверяется при каждом запуске — сменился (роутер выдал
другой) — адрес обновляется сам, смотреть в **Адрес для других устройств**.

| Условие | Почему |
| --- | --- |
| в сети Wi‑Fi есть интернет | имя `*.sslip.io` разрешает внешний DNS |
| роутер не блокирует ответы DNS с адресами локальной сети (защита от DNS rebinding) | иначе имя не откроется — лаунчер это проверяет и пишет причину; выход — раздать Wi‑Fi с телефона |
| сеть не гостевая и не общественная | там устройства часто изолированы друг от друга |
| только своя сеть | пароли демо-данных известны; платформу видят все в этой сети |

Не получилось (нет интернета, роутер блокирует) — лаунчер сообщит при запуске и на этот раз откроет платформу только
на этом компьютере. Выключение — тот же пункт меню; правило брандмауэра остаётся, но слушать сеть платформа перестаёт.

## Обновление

Разработка продолжается в репозитории; новая версия — новый инсталлятор (ниже). На компьютере с Windows — просто запустить
новый `DinastiaSetup-<версия>.exe` поверх: он остановит платформу, заменит программу (`app`, `runtime`), **данные в
`data\` сохранит** и применит новые миграции. Новые демо-данные (если сид изменился) — **Сбросить демо-данные…**.

## Удаление

«Параметры → Приложения → Dinastia → Удалить» (или «Пуск → Dinastia»). Удаление спросит, удалять ли и данные; «Нет» —
`C:\Dinastia\data` останется и подхватится следующей установкой.

## Если не запускается

| Признак | Что делать |
| --- | --- |
| «Порт N занят другой программой» | закрыть программу, перезагрузить компьютер; если постоянно — удалить с данными и установить заново (порты выберутся свободные) |
| окно не открывается, открывается Edge | нет WebView2 — лаунчер открывает учебный центр в Edge в режиме приложения; закрытие окна Edge останавливает платформу. Поставить WebView2 Runtime с сайта Microsoft |
| ошибка в окне запуска | текст ошибки и путь к логам — в окне; подробности — `launcher.log` и лог службы |
| установка сообщила, что подготовить базу не удалось | запустить Dinastia — лаунчер повторит подготовку |

## Сборка инсталлятора

Собрать `.exe` можно только на Windows (PyInstaller, Inno Setup), поэтому сборка — в CI:
`.github/workflows/windows.yml` (**Actions → Windows → Run workflow**; сам запускается при push в `main`, если менялся
пакет). Конвейер собирает инсталлятор, ставит его на чистый раннер, проверяет лаунчером (`Dinastia.exe --selftest`:
службы, вход слушателя, PDF через Chromium), ставит поверх как обновление, проверяет сетевой режим по IP раннера и
адресу `sslip.io` (`--selftest --network`) и удаляет. Инсталлятор — в **Artifacts**
запуска (zip с `DinastiaSetup-<версия>.exe`, хранится 30 дней). Версия — `ГГГГ.ММ.ДД-<коммит>`.

На своей Windows-машине (Node 24, pnpm, Python 3.12): `pwsh tools/windows/build.ps1 -Release <версия>` из корня
репозитория → `out\windows\DinastiaSetup-<версия>.exe`.

| Файл | Что |
| --- | --- |
| `tools/src/windows/app.ts` (`pnpm windows:app`) | приложение: сборка API и веба, сид, шлюз, зависимости API плоским `node_modules` → `out/windows/app` |
| `tools/src/windows/gateway.ts` | шлюз: статика веба, CSP (`apps/web/csp.ts`), прокси `/api` и `/health` с исходным Host |
| `tools/windows/launcher/dinastia.py` | лаунчер: службы, установка (`--setup`), проверка (`--selftest`), остановка (`--stop`), окно и меню |
| `tools/windows/installer/dinastia.iss` | инсталлятор: файлы, ярлыки, `--setup` после копирования, обновление, удаление |
| `tools/windows/build.ps1` | сборка целиком: среды выполнения (версии — в начале файла), Chromium, PyInstaller, Inno Setup |
| `tools/windows/selftest.ps1` | проверка в CI: установка → проверка → повторный запуск → обновление → удаление |

Меняются версии PostgreSQL, SeaweedFS, Mailpit или Node в `docker/compose.yml` / `.nvmrc` — поменять и в `build.ps1`.
Смена **мажорной** версии PostgreSQL на установленных компьютерах требует переноса данных (`pg_upgrade`) — до этого
пакет такую смену не поддерживает: удалить с данными и поставить заново.
