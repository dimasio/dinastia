# Инструкции для агентов (Dinastia)

Dinastia — SaaS-конструктор онлайн-школ (аналог Skillspace): школа создаёт курсы из блоков, ученики проходят уроки,
тесты и домашние задания, кураторы проверяют, школа видит прогресс. Мультитенантность: **тенант = школа**.

Технически — **модульный монолит на TypeScript** (pnpm + Turborepo): `apps/api` (Hono + oRPC + Drizzle + Postgres),
`apps/web` (React + Vite + TanStack Router/Query + shadcn/ui), общие пакеты в `packages/`.
«Low-code» — это **типизированные реестры** (блоки уроков, типы вопросов, админ-ресурсы, автоматизации) и генераторы:
новая возможность добавляется как запись реестра по контракту, а не правкой ядра.

- Документация — `docs/README.md`, правила — `docs/CONTRIBUTING.md`, архитектура — `docs/specs/architecture.md`,
  план — `docs/plan/roadmap.md`, решения — `docs/specs/decisions.md`.
- Язык документации, комментариев и UI-строк по умолчанию — русский; идентификаторы — английские.
- Команды — `pnpm …` из корня репозитория. Начало сессии и «что-то не стартует» — `pnpm env:check`.

## Две области работы

| Область                    | Что                                                                                                                                                                                                                                                | Где                                                                                                                                                                                                                            |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Продукт** (по умолчанию) | доменные модули, экраны, блоки уроков, типы вопросов, задачи, тесты к ним                                                                                                                                                                          | `apps/api/src/modules/**`, `apps/web/src/features/**`, `apps/web/src/routes/**`, `packages/contracts/**`, `packages/blocks/src/<тип>/**`, `packages/questions/src/<тип>/**`, `packages/i18n/locales/**`, `tests/**`, `docs/**` |
| **Ядро**                   | `apps/api/src/kernel/**` (БД, тенант, auth, oRPC, права, события, задачи, файлы, почта), `packages/ui/**` (дизайн-система и ресурс-фреймворк), механика реестров (`packages/*/src/registry*.ts`, `define*.ts`), генераторы `tools/**`, конфиги, CI | всё остальное                                                                                                                                                                                                                  |

Ядро правится, **только если человек в этой задаче прямо разрешил** («можно править ядро») или задача из роадмапа
относится к ядру (фазы 0–1, `docs/plan/roadmap.md`). Не хватает ядра для продуктовой задачи — **не обходи**:
оформи запрос `docs/tasks/requests/<slug>.md` (что нужно, зачем, что пробовал, пример) и скажи человеку; есть путь
существующими средствами — сделай им и упомяни запрос; нет — остановись.

## Сначала план — потом правки

Перед первой правкой покажи человеку план:

1. шаги — что меняется (таблица, контракт, сервис, экран, блок…) и в каком модуле;
2. для каждого шага — чем он делается (скилл, генератор `pnpm gen:*`, существующий компонент `packages/ui`, хелпер ядра);
3. **блокеры** — чего нет в ядре; миграции БД и изменения контрактов — отдельной строкой (это необратимо/ломает клиентов).

## Скиллы

Скилл — инструкция для задачи: `docs/skills/<уровень>/<скилл>/SKILL.md` (ссылки — `.claude/skills/<имя>`,
`pnpm skills:link`). Правила — `docs/skills/README.md`. **Прежде чем делать задачу вида X, открой скилл вида X.**

### Процесс

| Задача                                                                                                                           | Скилл                 |
| -------------------------------------------------------------------------------------------------------------------------------- | --------------------- |

| выполнить задачу фазы роадмапа (ядро, инфраструктура)                                                                            | `roadmap-task`        |
| спроектировать новую крупную возможность (оплаты, чаты, геймификация…) до разработки                                             | `feature-design`      |

| ревью изменений и самопроверка перед «готово»                                                                                    | `review-checklist`    |
| просмотр интерфейса глазами: снимки светлой и тёмной темы и 375px перед «готово»                                                 | `visual-review`       |
| найти и исправить ошибку                                                                                                         | `debugging`           |

## Правила

1. **Тенант.** Каждая таблица с данными школы — через `tenantColumns()` и RLS (скилл `db-schema`); запросы — только
   через `ctx.db` из контекста процедуры, никогда не через глобальный клиент. `school_id` в фильтрах руками не пишется.
2. **Контракт — источник правды API.** Схемы входа/выхода — zod в `packages/contracts`; типы клиента не пишутся руками.
3. **Секреты ответов не уходят ученику.** Данные блоков и вопросов ученику — только через `toPublic()` (скиллы
   `lesson-blocks`, `question-types`).
4. **Миграции не редактируются после мержа**; новая миграция — `pnpm db:generate`. Миграцию, удаляющую данные или
   колонку, — согласовать с человеком.
5. **Права** — каждая процедура объявляет разрешение (`.use(can('…'))`) или явно `public`; UI прячет, сервер запрещает.
6. **Строки UI** — через i18n-ключи, не литералами в JSX (скилл `i18n`).
7. **Готово** — когда `pnpm check` зелёный (typecheck, lint, unit, проверка реестров, `docs:check`) и для фич —
   e2e-сценарий зелёный (`pnpm e2e -- <сценарий>`). Падающий существующий тест не ослаблять и не удалять — сообщить.
8. Имена модулей, процессов, ролей и новых сущностей предметной области даёт человек; не назвал — спроси.
9. Не коммитить и не пушить без просьбы человека. Не работать с продовыми БД и ключами.
10. Изменился процесс — в той же задаче правится продуктовый скилл и спека (`docs/specs/domain.md`).
11. Термины в UI и документах — только из `docs/specs/glossary.md`.
12. Перед «готово» — самопроверка по `review-checklist`; признаки утечки между школами, ответов ученикам или ПДн —
    сразу сообщить человеку (`security-baseline`).
13. Длинная задача прерывается — `docs/tasks/<задача>/notes/handoff.md` (`agent-collaboration`).
